Guía de estudio de PHP

Del primer echo a una aplicación MVC segura. Cada sección depende de la anterior: síguelas en orden y practica cada ejemplo.

1. Entorno y primer script

Instala PHP 8.3+ (o XAMPP/Laragon), MySQL/MariaDB y un editor (VS Code). Ejecuta scripts con php archivo.php o el servidor integrado.

php -v
php -S localhost:8000 -t public   # servidor de desarrollo
<?php
echo "Hola, mundo";      // salida
print("Otra forma");
// comentario de línea   # otro   /* bloque */
?>

Cada instrucción termina en ;. En archivos solo PHP omite la etiqueta de cierre ?>.

4. Funciones

8. Archivos y subidas

$txt = file_get_contents("datos.txt");  file_put_contents("log.txt", "linea\n", FILE_APPEND);

Nunca uses el nombre ni la extensión que envía el usuario. Guarda las subidas fuera de la carpeta pública cuando sea posible.

9. MySQL con PDO

CREATE TABLE usuarios (
  id INT AUTO_INCREMENT PRIMARY KEY,
  nombre VARCHAR(80) NOT NULL,
  email VARCHAR(120) NOT NULL UNIQUE,
  password VARCHAR(255) NOT NULL,
  creado TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
$pdo = new PDO("mysql:host=localhost;dbname=app;charset=utf8mb4", $user, $pass, [
    PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
    PDO::ATTR_EMULATE_PREPARES   => false,
]);
$st = $pdo->prepare("SELECT * FROM usuarios WHERE email = :e");
$st->execute([':e' => $email]);
$u = $st->fetch();            // una fila; fetchAll() para todas
$pdo->lastInsertId();
$pdo->beginTransaction(); /* ... */ $pdo->commit();   // o rollBack()
Nunca concatenes variables en el SQL. Las consultas preparadas son la defensa contra la inyección SQL.

10. CRUD completo

CRUD = Create, Read, Update, Delete. Ejemplo sobre la tabla productos(id, nombre, precio):

// CREATE
$pdo->prepare("INSERT INTO productos (nombre, precio) VALUES (?, ?)")->execute([$n, $p]);
// READ (listado con paginación)
$st = $pdo->prepare("SELECT * FROM productos ORDER BY id DESC LIMIT :l OFFSET :o");
$st->bindValue(':l', 10, PDO::PARAM_INT); $st->bindValue(':o', ($pag-1)*10, PDO::PARAM_INT);
$st->execute(); $filas = $st->fetchAll();
// UPDATE
$pdo->prepare("UPDATE productos SET nombre = ?, precio = ? WHERE id = ?")->execute([$n, $p, $id]);
// DELETE
$pdo->prepare("DELETE FROM productos WHERE id = ?")->execute([$id]);

Flujo típico de pantallas: index.php (lista) → crear.php (formulario POST) → editar.php?id= → borrar.php (solo POST con token CSRF). Tras cada escritura, redirige con header("Location: ...").

11. Programación orientada a objetos

declare(strict_types=1);
interface Describible { public function describir(): string; }
abstract class Modelo { abstract public function tabla(): string; }
trait Fechas { public function ahora(): string { return date('c'); } }
enum Estado: string { case Activo = 'activo'; case Baja = 'baja'; }

final class Producto extends Modelo implements Describible {
    use Fechas;
    private static int $total = 0;
    public function __construct(
        private string $nombre,
        protected float $precio,
        public readonly Estado $estado = Estado::Activo,
    ) { self::$total++; }
    public function tabla(): string { return 'productos'; }
    public function describir(): string { return "{$this->nombre}: {$this->precio}"; }
    public function getNombre(): string { return $this->nombre; }
    public static function total(): int { return self::$total; }
}
$p = new Producto("Teclado", 25.5);
echo $p->describir(); echo Producto::total();
ConceptoPara qué sirve
Encapsulaciónprivate/protected/public protegen el estado interno
Herencia / interfacesReutilizar y definir contratos; prefiere composición sobre herencia profunda
Excepcionestry { } catch (Throwable $e) { } finally { } y throw new DomainException()
Inyección de dependenciasPasar colaboradores (ej. PDO) por el constructor, no crearlos dentro

Principios útiles: SOLID, una clase = una responsabilidad, y tipado estricto en todo.

13. Patrón MVC

proyecto/
├── public/          index.php, css/, js/   (única carpeta expuesta)
├── src/
│   ├── Controllers/ ProductoController.php
│   ├── Models/      Producto.php
│   ├── Core/        Router.php, Database.php, View.php
│   └── Views/       productos/index.php
├── config/ · storage/ · vendor/ · .env · composer.json

Modelo = datos y reglas; Vista = HTML; Controlador = recibe la petición, usa el modelo y elige la vista.

// public/index.php (front controller)
$router = new App\Core\Router();
$router->get('/productos', [ProductoController::class, 'index']);
$router->post('/productos', [ProductoController::class, 'store']);
$router->dispatch($_SERVER['REQUEST_METHOD'], parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH));

// Router.php
final class Router {
    private array $rutas = [];
    public function get(string $p, array $h): void  { $this->rutas['GET'][$p] = $h; }
    public function post(string $p, array $h): void { $this->rutas['POST'][$p] = $h; }
    public function dispatch(string $m, string $uri): void {
        [$clase, $metodo] = $this->rutas[$m][$uri] ?? [null, null];
        if (!$clase) { http_response_code(404); echo "No encontrado"; return; }
        (new $clase(Database::pdo()))->$metodo();
    }
}

// ProductoController.php
final class ProductoController {
    public function __construct(private PDO $pdo) {}
    public function index(): void {
        $productos = (new Producto($this->pdo))->todos();
        View::render('productos/index', compact('productos'));
    }
}

// View.php + vista
final class View { public static function render(string $v, array $d = []): void {
    extract($d); require __DIR__ . "/../Views/$v.php"; } }
// Views/productos/index.php
<?php foreach ($productos as $p): ?>
  <li><?= htmlspecialchars($p['nombre']) ?></li>
<?php endforeach; ?>

Apache: añade .htaccess en public/ con RewriteRule ^ index.php [L] para que todas las URL pasen por el front controller. Cuando el proyecto crezca, usa Laravel o Symfony, que implementan estas ideas.

14. Seguridad en PHP

Contraseñas

$hash = password_hash($pass, PASSWORD_DEFAULT);          // registro
if ($u && password_verify($pass, $u['password'])) { session_regenerate_id(true); }
if (password_needs_rehash($u['password'], PASSWORD_DEFAULT)) { /* actualizar hash */ }

No uses md5 ni sha1. Mensaje de error genérico: "Credenciales incorrectas".

Inyección SQL

Solo consultas preparadas (sección 9). Para nombres dinámicos de columnas o tablas usa una lista blanca: in_array($col, ['nombre','precio'], true).

XSS

function e(?string $s): string { return htmlspecialchars($s ?? '', ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8'); }
// Cabecera adicional
header("Content-Security-Policy: default-src 'self'");

CSRF

$_SESSION['csrf'] ??= bin2hex(random_bytes(32));
// en el formulario:
// <input type="hidden" name="csrf" value="<?= e($_SESSION['csrf']) ?>">
if (!hash_equals($_SESSION['csrf'] ?? '', $_POST['csrf'] ?? '')) { http_response_code(419); exit; }

Autorización

Comprueba el permiso en el servidor en cada acción, y que el recurso pertenezca al usuario (WHERE id = ? AND user_id = ?). Esconder un botón no protege nada (IDOR).

Otras defensas

RiesgoDefensa
Subidas de archivosValidar MIME real, tamaño, renombrar, no ejecutar en la carpeta destino
Fuerza brutaLimitar intentos por IP y cuenta, retraso progresivo, 2FA
Fijación de sesiónsession_regenerate_id(true), cookies HttpOnly, Secure, SameSite
Inclusión de archivosNunca hacer include $_GET['p']; usar lista blanca de rutas
Redirección abiertaValidar el destino contra rutas propias
DeserializaciónNo usar unserialize() con datos del usuario; preferir JSON

Regla de oro: toda entrada es hostil. Valida al entrar, escapa al salir y aplica el mínimo privilegio (usuario de base de datos con permisos limitados).

Manejo de errores y logs

set_exception_handler(function (Throwable $e) {
    error_log($e->getMessage() . "\n" . $e->getTraceAsString());
    http_response_code(500); echo "Error interno";
});
error_reporting(E_ALL);

Características modernas de PHP 8

  • Promoción de propiedades, readonly, enums, match, operador ?->, argumentos con nombre, tipos unión, never, atributos #[Route], fibers.

Otros pilares profesionales

  • Pruebas: PHPUnit (composer require --dev phpunit/phpunit) y Pest. Prueba reglas de negocio primero.
  • Calidad: PHPStan o Psalm, PHP-CS-Fixer, estándar PSR-12.
  • Rendimiento: OPcache, índices SQL, evitar consultas N+1, caché con Redis o APCu.
  • Tareas en segundo plano: colas (Redis, RabbitMQ, Symfony Messenger) y cron para correos y reportes.
  • Correo: PHPMailer o Symfony Mailer con SMTP autenticado.
  • Migraciones: Phinx o Doctrine Migrations para versionar la base de datos.
  • Frameworks: Laravel (el más popular), Symfony (empresarial), Slim (microservicios).
  • Despliegue: Git, Docker, Nginx + PHP-FPM, CI/CD con GitHub Actions, variables de entorno por entorno.

16. Proyecto real y ruta de estudio

Construye en este orden una gestión de tareas o inventario con usuarios:

  1. Diseña la base de datos (usuarios, tareas, relaciones y claves foráneas).
  2. Estructura MVC con Composer, autoload y .env.
  3. Registro, login y cierre de sesión con password_hash y CSRF.
  4. CRUD de tareas con PDO, validación y paginación, siempre filtrado por usuario.
  5. Roles y permisos (usuario/admin) comprobados en el servidor.
  6. Subida de adjuntos con validación estricta.
  7. API JSON para consumo desde JavaScript o móvil.
  8. Pruebas, logs, cabeceras de seguridad y despliegue con HTTPS.
Siguiente paso recomendado: repite el proyecto con Laravel para ver cómo el framework resuelve rutas, ORM (Eloquent), validación, autenticación y migraciones. Con las bases de esta guía lo entenderás por dentro.
