Ethical Hacking · Password Auditing · Command Reference

Organized by practical workflow, from setup to reporting.

Authorized use only

Use Hashcat only on hashes you own or have explicit permission to audit. Keep recovered passwords confidential. Use synthetic training data for practice.

1. Recommended workflow

  1. Confirm authorization and prepare a test hash file.
  2. Check the Hashcat version and available compute devices.
  3. Identify the hash algorithm and the required input format.
  4. Choose the correct hash mode with -m.
  5. Choose an attack mode with -a.
  6. Run a small, controlled test against a lab hash.
  7. Monitor the session and save the results securely.
  8. Document findings and recommend stronger password storage.

3. Basic command syntax

hashcat [options] HASH_FILE [WORDLIST|MASK|OTHER_INPUT]
ArgumentMeaning
-m MODEHash type / algorithm mode.
-a MODEAttack mode.
-r FILEApply a rule file where supported.
-o FILEWrite recovered results to a file.
--session NAMEName a session for tracking and recovery.
--statusDisplay status information.
--status-timer NSet the status update interval in seconds.
--showDisplay hashes already recovered in the potfile.
--leftDisplay hashes not yet recovered, based on the potfile.
--restoreResume a saved session.
--potfile-path FILESpecify a potfile location.
--outfile-format NChoose output fields; consult help for supported format numbers.
--identify FILEIdentify possible hash types when supported by your version.

Options may change between releases. Consult the installed help for exact syntax and compatibility.

4. Hash types and modes

The -m option selects a hash mode. The following are common examples, not a complete list.

ModeHash typeNotes
0MD5Fast legacy hash; unsuitable for password storage.
100SHA-1General-purpose legacy hash.
1400SHA-256Raw SHA-256 digest.
1700SHA-512Raw SHA-512 digest.
1000NTLMWindows NT password hash format.
3200bcryptAdaptive password hash.
1800sha512cryptUnix/Linux password hash format.
22000WPA-PBKDF2-PMKID+EAPOLWi-Fi capture format, requiring compatible input.
Important:

A hash's appearance alone does not always uniquely identify its algorithm. Salts, iterations, encodings, and application-specific formats matter. Verify the format before choosing a mode.

5. Attack modes

ModeNameExplanation
-a 0StraightTests candidates from a wordlist.
-a 1CombinationCombines entries from two wordlists.
-a 3MaskGenerates candidates from a defined character pattern.
-a 6Wordlist + maskAdds a mask-generated suffix to wordlist candidates.
-a 7Mask + wordlistAdds mask-generated characters before wordlist candidates.

Mode 0: Wordlist

hashcat -m 0 -a 0 lab.hash lab-wordlist.txt

Uses each candidate from the supplied wordlist.

Mode 1: Combination

hashcat -m 0 -a 1 lab.hash words-a.txt words-b.txt

Combines words from two lists. Use only in a controlled lab.

Mode 3: Mask

hashcat -m 0 -a 3 lab.hash '?d?d?d?d'

Demonstrates a four-digit candidate pattern against a synthetic training hash.

Mode 6: Wordlist plus mask

hashcat -m 0 -a 6 lab.hash lab-wordlist.txt '?d?d'

Appends two digits to each wordlist candidate.

Mode 7: Mask plus wordlist

hashcat -m 0 -a 7 lab.hash '?d?d' lab-wordlist.txt

Prepends two digits to each wordlist candidate.

6. Rules and masks

Rule-based candidate transformation

hashcat -m 0 -a 0 lab.hash lab-wordlist.txt \
  -r rules/best66.rule

Rules transform candidate words, for example by changing case or adding characters. Rule files must exist at the specified path.

Built-in mask character sets

TokenCharacter set
?lLowercase letters: a-z
?uUppercase letters: A-Z
?dDigits: 0-9
?hLowercase hexadecimal: 0-9, a-f
?HUppercase hexadecimal: 0-9, A-F
?sSpecial characters in Hashcat's built-in set
?aCombined lowercase, uppercase, digits, and special characters
?bAny byte value

Custom character sets can be defined using -1, -2, -3, or -4. Check hashcat --help for syntax.

7. Running and monitoring an audit

Named session

hashcat -m 0 -a 0 lab.hash lab-wordlist.txt \
  --session lab-session --status --status-timer 30

Request status during a running session

s

In the interactive Hashcat terminal, s requests status. Other interactive commands are version-dependent; consult the official documentation.

Stop gracefully

q

In an interactive session, q requests a quit. A resumable restore file may be written unless restore functionality has been disabled. Avoid terminating the process abruptly.

8. Results, potfiles, and restore

Write recovered results to a file

hashcat -m 0 -a 0 lab.hash lab-wordlist.txt \
  -o recovered-lab.txt

Display previously recovered hashes

hashcat -m 0 lab.hash --show

List hashes that remain unrecovered

hashcat -m 0 lab.hash --left

Resume a named session

hashcat --session lab-session --restore

Restore files depend on the session and execution environment. Use the same working directory and configuration where possible.

Choose a custom potfile

hashcat -m 0 -a 0 lab.hash lab-wordlist.txt \
  --potfile-path lab.potfile

The potfile stores recovered hash/password associations. Protect it as sensitive data and do not publish it with your lab report.

9. Troubleshooting checklist

  • Token or line-length errors: Check the selected hash mode, salt format, separators, and input encoding.
  • No devices found: Inspect hashcat -I, then check the relevant GPU/CPU runtime and driver installation.
  • Zero recovered hashes: Confirm the hash and mode, candidate list, rule path, and attack assumptions.
  • Unexpected output: Review outfile formatting and whether the potfile already contains the hash.
  • Session won't resume: Verify the session name, restore file, and working directory.
  • Very slow performance: Compare benchmark results, algorithm cost, device support, and workload size.
