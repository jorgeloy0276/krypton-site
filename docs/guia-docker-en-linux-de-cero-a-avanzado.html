1. Qué es Docker

Docker empaqueta una aplicación con todo lo que necesita para funcionar, de modo que corre igual en tu laptop, en un servidor o en la nube.

  • Imagen: plantilla de solo lectura (por ejemplo nginx).
  • Contenedor: una imagen en ejecución. Es desechable.
  • Volumen: carpeta persistente. Sin volumen, los datos se pierden al borrar el contenedor.
  • Red: canal por el que los contenedores se hablan entre sí.
  • Compose: un archivo compose.yaml que describe varios contenedores y se levanta con un solo comando.

2. Instalación (Ubuntu / Debian)

Usa el repositorio oficial. El paquete docker.io de Ubuntu suele ir atrasado y no es el recomendado.

Paso 1: comprueba tu sistema

. /etc/os-release && echo "$PRETTY_NAME"; uname -m

Necesitas una versión de 64 bits soportada. La lista vigente está en docs.docker.com/engine/install.

Paso 2: elimina paquetes que chocan

sudo apt remove $(dpkg --get-selections docker.io docker-compose docker-compose-v2 docker-doc podman-docker containerd runc | cut -f1)

Si dice que no hay nada instalado, está bien.

Paso 3: agrega el repositorio de Docker

Este ejemplo es para Ubuntu. En Debian cambia ubuntu por debian en las dos URL.

sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update

Paso 4: instala Docker Engine y Compose

sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Paso 5: verifica

sudo systemctl status docker --no-pager
sudo docker run hello-world
docker --version
docker compose version

Si ves el mensaje “Hello from Docker!”, ya funciona.

Otras distros. Fedora: sudo dnf config-manager addrepo --from-repofile=https://download.docker.com/linux/fedora/docker-ce.repo y luego sudo dnf install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin. Atajo solo para aprender: curl -fsSL https://get.docker.com | sudo sh. En servidores reales prefiere el repositorio, porque el script puede subir de versión mayor sin avisar.

3. Configuración inicial

Usar Docker sin escribir sudo

sudo usermod -aG docker $USER
newgrp docker
docker run --rm hello-world
Ojo: pertenecer al grupo docker equivale a tener permisos de root en la máquina. Hazlo solo con usuarios de confianza.

Arrancar con el sistema

sudo systemctl enable --now docker containerd

Limitar el tamaño de los logs

Sin límite, los logs pueden llenar el disco. Crea /etc/docker/daemon.json:

{
  "log-driver": "json-file",
  "log-opts": { "max-size": "10m", "max-file": "3" }
}
sudo systemctl restart docker

Afecta a los contenedores que crees después del reinicio.

4. Comandos esenciales

docker run -d --name web -p 8080:80 nginx   # crea y arranca en segundo plano
docker ps                                   # contenedores activos (-a: todos)
docker logs -f web                          # ver logs en vivo
docker exec -it web sh                      # entrar al contenedor
docker stop web && docker rm web            # detener y borrar
docker images                               # imágenes locales
docker pull nginx:1.27                      # descargar una versión concreta
docker rmi nginx                            # borrar imagen
docker stats                                # CPU y RAM en vivo

Abre http://localhost:8080 para ver nginx. En -p 8080:80, el primer número es el puerto de tu máquina y el segundo el del contenedor.

Evita la etiqueta latest en proyectos serios. Fija una versión (nginx:1.27) para que una actualización no te rompa nada por sorpresa.

5. Volúmenes y redes

Volúmenes (datos que sobreviven)

docker volume create datos
docker run -d --name db -e POSTGRES_PASSWORD=cambiame \
  -v datos:/var/lib/postgresql/data postgres:17
docker volume ls
docker volume inspect datos

Un bind mount enlaza una carpeta de tu disco: -v $(pwd)/site:/usr/share/nginx/html:ro. El :ro lo deja de solo lectura.

Redes (que los contenedores se vean)

docker network create mired
docker run -d --name api --network mired miimagen
docker run --rm --network mired curlimages/curl http://api:3000

En una red creada por ti, los contenedores se resuelven por su nombre (api, db). Nunca uses localhost para llegar a otro contenedor: cada uno tiene su propio localhost.

6. Crear tu propia imagen

Archivo Dockerfile de ejemplo para una app Python:

FROM python:3.13-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
USER 10001
CMD ["python", "app.py"]
docker build -t miapp:1.0 .
docker run -d -p 5000:5000 miapp:1.0

Copiar primero requirements.txt aprovecha la caché: si solo cambias tu código, Docker no reinstala las dependencias. Añade un archivo .dockerignore con .git, node_modules y .env para no meter basura ni secretos en la imagen.

7. Docker Compose

Crea una carpeta con este compose.yaml. No lleva la línea version:, porque ya está obsoleta.

services:
  web:
    image: nginx:1.27
    ports: ["127.0.0.1:8080:80"]
    volumes: ["./site:/usr/share/nginx/html:ro"]
    depends_on:
      db: { condition: service_healthy }
    restart: unless-stopped
  db:
    image: postgres:17
    environment:
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes: ["dbdata:/var/lib/postgresql/data"]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      retries: 10
    restart: unless-stopped
volumes:
  dbdata:
echo "DB_PASSWORD=$(openssl rand -hex 16)" > .env
mkdir site && echo "<h1>Hola Docker</h1>" > site/index.html
docker compose up -d        # levantar
docker compose ps           # estado
docker compose logs -f web  # logs
docker compose down         # apagar (conserva volúmenes)
docker compose down -v      # apagar y BORRAR datos

8. Nivel avanzado

Seguridad de puertos y firewall

Docker escribe sus propias reglas de red y puede saltarse UFW. Un puerto publicado como -p 5432:5432 queda abierto a internet aunque UFW diga que no. Publica solo en local cuando no necesites acceso externo: -p 127.0.0.1:5432:5432. Si accedes desde fuera, ponlo detrás de un proxy inverso con HTTPS.

Límites de recursos y endurecimiento

docker run -d --name app --memory 512m --cpus 1 \
  --read-only --tmpfs /tmp --cap-drop ALL \
  --security-opt no-new-privileges miimagen

Políticas de reinicio

restart: unless-stopped reinicia el contenedor tras un fallo o un reinicio del servidor, salvo que lo detengas tú.

Imágenes pequeñas con multi-stage

Compila en una etapa y copia solo el resultado a una imagen final ligera:

FROM node:24 AS build
WORKDIR /src
COPY . .
RUN npm ci && npm run build

FROM nginx:1.27-alpine
COPY --from=build /src/dist /usr/share/nginx/html

Respaldar y restaurar un volumen

docker run --rm -v datos:/d -v $(pwd):/b alpine tar czf /b/datos.tgz -C /d .
docker run --rm -v datos:/d -v $(pwd):/b alpine tar xzf /b/datos.tgz -C /d

Limpieza de disco

docker system df            # cuánto ocupa todo
docker system prune         # borra lo no usado (contenedores parados, redes, caché)
docker image prune -a       # borra imágenes sin contenedor

Otras herramientas que conviene conocer

  • Rootless: Docker sin privilegios de root (dockerd-rootless-setuptool.sh install), más seguro y con algunas limitaciones.
  • Buildx: construye imágenes para varias arquitecturas, por ejemplo --platform linux/amd64,linux/arm64.
  • Context: docker context create srv --docker "host=ssh://usuario@servidor" controla un Docker remoto por SSH.
  • Actualizar: sudo apt update && sudo apt install --only-upgrade docker-ce docker-ce-cli containerd.io docker-compose-plugin.
  • GPU NVIDIA: instala nvidia-container-toolkit y usa --gpus all. Lo necesitarás para correr IA local rápida.

9. Solución de problemas

SíntomaCausa probable y solución
permission denied ... docker.sockNo estás en el grupo docker. Ejecuta sudo usermod -aG docker $USER y vuelve a iniciar sesión.
port is already allocatedOtro programa usa ese puerto. Revisa con sudo ss -tlnp | grep 8080 o cambia el puerto.
El contenedor se detiene al instanteMira docker logs nombre. Casi siempre falta una variable de entorno o el comando falló.
Un contenedor no alcanza a otroDeben estar en la misma red y usar el nombre del servicio, no localhost.
Disco llenoEjecuta docker system df y luego docker system prune. Configura la rotación de logs (sección 3).
apt update falla tras añadir el repoRevisa el nombre de versión con . /etc/os-release && echo $VERSION_CODENAME y el archivo docker.sources.
