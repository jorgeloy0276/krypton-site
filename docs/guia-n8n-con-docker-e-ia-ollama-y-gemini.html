n8n con Docker e IA: Ollama (local) y Gemini (gratis)

Instala n8n con PostgreSQL usando Docker Compose y conéctalo a un modelo local con Ollama o a la API gratuita de Gemini. Verificada en noviembre de 2026. Requiere tener Docker listo (ver la guía de Docker en Linux).

Versión importante: n8n 3.0 salió en beta el 27 de octubre de 2026 y su versión estable llegará a inicios de diciembre. Esta guía fija una versión 2.x estable, que es lo prudente para aprender. Más adelante verás cómo migrar a 3.x. Desde 3.0, n8n autoalojado solo se admite con Docker, así que vas por el camino correcto.

1. Qué vas a montar

n8n es una herramienta visual para automatizar tareas conectando servicios. Sus nodos de IA le permiten usar un modelo de lenguaje para resumir, clasificar, responder o decidir. Necesitas dos piezas: n8n (con su base de datos) y un “cerebro” de IA. Elige según tu caso:

Ollama (local)Gemini (API gratuita)
CostoGratis; usa tu hardwareGratis con límites de uso
PrivacidadLos datos no salen de tu equipoSe envían a Google; en el nivel gratuito pueden usarse para mejorar sus productos, así que no mandes datos sensibles
CalidadDepende del modelo y de tu RAM/GPUAlta, sin exigir hardware
Requisitos8 GB de RAM para modelos de 1 a 4B; 16 GB para 7 a 8BCuenta de Google e internet

Puedes configurar ambos y alternar entre ellos. Se recomienda un equipo con al menos 4 GB de RAM libres para n8n y PostgreSQL, además de lo que pida el modelo.

2. Prueba rápida (un solo comando)

Sirve para ver n8n funcionando en un minuto. Los datos se guardan en un volumen, pero para uso real pasa a la sección 3.

docker volume create n8n_data
docker run -it --rm --name n8n -p 127.0.0.1:5678:5678 \
  --add-host host.docker.internal:host-gateway \
  -v n8n_data:/home/node/.n8n \
  docker.n8n.io/n8nio/n8n

Abre http://localhost:5678, crea la cuenta de propietario y listo. Detén con Ctrl+C. El flag --add-host permite que n8n llegue a servicios de tu máquina, como Ollama, usando el nombre host.docker.internal (en Linux no existe por defecto).

3. Instalación completa con Compose + PostgreSQL

Paso 1: carpeta y variables

mkdir -p ~/n8n && cd ~/n8n
sudo apt install -y jq openssl
N8N_VERSION=$(curl -fsSL https://registry.npmjs.org/-/package/n8n/dist-tags | jq -r .stable)
echo "$N8N_VERSION"

Si el número empieza con 2., úsalo. Si empieza con 3., la versión 3 ya es estable y la guía sigue valiendo, pero lee antes las notas de cambios en docs.n8n.io. Crea el archivo .env:

umask 077
cat > .env <<EOF
N8N_VERSION=$N8N_VERSION
POSTGRES_PASSWORD=$(openssl rand -hex 24)
N8N_ENCRYPTION_KEY=$(openssl rand -hex 32)
TIMEZONE=UTC
EOF
cat .env
Guarda una copia de .env fuera del servidor (por ejemplo en un gestor de contraseñas). La N8N_ENCRYPTION_KEY cifra tus credenciales; si la pierdes, tendrás que volver a ingresar todas tus claves. Cambia TIMEZONE a tu zona, por ejemplo America/Panama o Europe/Madrid.

Paso 2: archivo compose.yaml

services:
  postgres:
    image: postgres:17
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
    volumes: ["pgdata:/var/lib/postgresql/data"]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    ports: ["127.0.0.1:5678:5678"]
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      GENERIC_TIMEZONE: ${TIMEZONE}
      TZ: ${TIMEZONE}
    extra_hosts: ["host.docker.internal:host-gateway"]
    volumes: ["n8n_data:/home/node/.n8n"]
    depends_on:
      postgres: { condition: service_healthy }

  # IA local dentro de Compose (opcional, ver sección 4, opción B)
  ollama:
    image: ollama/ollama
    profiles: ["ia"]
    restart: unless-stopped
    volumes: ["ollama:/root/.ollama"]

volumes:
  pgdata:
  n8n_data:
  ollama:

Paso 3: arrancar y entrar

docker compose up -d
docker compose ps
docker compose logs -f n8n

Abre http://localhost:5678 y crea primero la cuenta de propietario. Los puertos están publicados solo en 127.0.0.1 a propósito: nadie en tu red puede entrar sin pasar por un proxy HTTPS. Si n8n corre en un servidor remoto, accede con un túnel SSH: ssh -L 5678:127.0.0.1:5678 usuario@servidor.

En la versión 2.x, los nodos Code se ejecutan en “task runners” de forma predeterminada y el acceso a variables de entorno desde el nodo Code está bloqueado. No necesitas N8N_RUNNERS_ENABLED: si lo ves en tutoriales viejos, ignóralo.

4. IA local con Ollama

Opción A: Ollama instalado en tu Linux (recomendada si tienes GPU)

curl -fsSL https://ollama.com/install.sh | sh
ollama pull llama3.2:3b
ollama run llama3.2:3b "Responde en una frase: ¿qué es Docker?"

Ollama escucha solo en 127.0.0.1, así que el contenedor de n8n no lo alcanza. Ábrelo a la red de Docker:

sudo systemctl edit ollama
# Pega esto en el editor y guarda:
[Service]
Environment="OLLAMA_HOST=0.0.0.0:11434"

sudo systemctl daemon-reload && sudo systemctl restart ollama
Seguridad: 0.0.0.0 expone Ollama a toda tu red, y no tiene contraseña. Si tu equipo está en una red que no es de confianza, bloquea el puerto desde fuera con tu firewall y deja pasar solo el tráfico de Docker, o usa la opción B.

En n8n usarás la URL http://host.docker.internal:11434.

Opción B: Ollama dentro de Compose (más simple y aislada)

docker compose --profile ia up -d
docker compose exec ollama ollama pull llama3.2:3b

Aquí no se publica ningún puerto: n8n lo alcanza por el nombre del servicio en la URL http://ollama:11434. Funciona con CPU. Para usar una GPU NVIDIA, instala nvidia-container-toolkit y añade bajo ollama:

    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: all
              capabilities: [gpu]

Elegir modelo

  • 8 GB de RAM: modelos de 1 a 4B (por ejemplo llama3.2:3b, gemma3:4b).
  • 16 GB de RAM: 7 a 8B (por ejemplo qwen3:8b).
  • Para agentes que usan herramientas, elige un modelo con la etiqueta “tools” en ollama.com/library. Allí verás también los modelos más nuevos.
  • Para búsqueda por documentos (RAG), añade un modelo de embeddings: ollama pull nomic-embed-text.

Conectar Ollama a n8n

  1. En n8n abre Credentials → Create credential y elige Ollama.
  2. En Base URL pon http://host.docker.internal:11434 (opción A) o http://ollama:11434 (opción B).
  3. Pulsa Save. Debe aparecer “Connection tested successfully”.

Si ves un error con ::1, cambia localhost por 127.0.0.1 en la URL.

5. IA gratuita con Gemini

  1. Entra a aistudio.google.com con tu cuenta de Google y pulsa Get API key → Create API key. No necesitas tarjeta para el nivel gratuito.
  2. Copia la clave y guárdala en un lugar seguro.
  3. En n8n crea la credencial Google Gemini(PaLM) API. Pega la clave y deja el host por defecto (https://generativelanguage.googleapis.com).
  4. Al usar el nodo Google Gemini Chat Model, elige un modelo “Flash” de la lista que carga solo. Son los más rápidos y los que suelen tener cupo gratuito.
Los límites del nivel gratuito (peticiones por minuto y por día) cambian y dependen del modelo. Consúltalos con tu sesión iniciada en aistudio.google.com/rate-limit. Si ves errores 429, espera o activa Retry On Fail en la configuración del nodo.

Otros proveedores con plan gratuito

Servicios como OpenRouter o Groq ofrecen API compatible con OpenAI y suelen tener modelos o cupos gratuitos (verifica sus condiciones actuales). En n8n crea una credencial OpenAI, cambia la Base URL (https://openrouter.ai/api/v1 o https://api.groq.com/openai/v1) y usa el nodo OpenAI Chat Model.

6. Tu primer agente de IA

  1. En Workflows pulsa Create workflow.
  2. Agrega el nodo Chat Trigger (“On chat message”).
  3. Agrega el nodo AI Agent y conéctalo al trigger.
  4. En su entrada Chat Model pulsa “+” y elige Ollama Chat Model (o Google Gemini Chat Model). Selecciona tu credencial y el modelo.
  5. En Memory agrega Simple Memory para que recuerde la conversación.
  6. En Tool agrega Calculator o Wikipedia para probar herramientas.
  7. Pulsa Open chat y escribe: “¿Cuánto es 1234 por 56 y quién inventó el teléfono?”.
Hay dos nodos de Ollama: Ollama Chat Model funciona con agentes y herramientas; Ollama Model sirve solo para texto simple. Si no necesitas decisiones ni herramientas, usa el nodo Basic LLM Chain: es más rápido y funciona con cualquier modelo.

Llamar a Ollama sin nodos de IA

Prueba la API desde la terminal:

curl http://localhost:11434/api/generate \
  -d '{"model":"llama3.2:3b","prompt":"Resume: Docker empaqueta apps.","stream":false}'

En n8n usa un nodo HTTP Request: método POST, URL http://host.docker.internal:11434/api/generate, cuerpo JSON con el mismo contenido, y lee el texto en el campo response. Combínalo con un nodo Webhook para crear tu propia API de IA.

7. Nivel avanzado

Webhooks y HTTPS

Para que servicios externos (Telegram, Stripe, formularios) llamen a n8n necesitas una URL pública con HTTPS. Opciones: Cloudflare Tunnel, o un proxy como Caddy. Luego añade en environment:

      WEBHOOK_URL: https://n8n.tudominio.com/
      N8N_EDITOR_BASE_URL: https://n8n.tudominio.com
      N8N_PROXY_HOPS: 1

Sin WEBHOOK_URL, n8n mostrará direcciones con localhost que nadie podrá usar. No desactives N8N_SECURE_COOKIE salvo en una red local de confianza sin HTTPS.

Modelo de respaldo y mezcla de IAs

Un patrón útil: Ollama como modelo principal (gratis y privado) y Gemini como respaldo si falla. En el AI Agent de las versiones recientes puedes activar un modelo de respaldo en sus opciones. También puedes usar Ollama para datos sensibles y Gemini para tareas que exijan más calidad.

RAG: que la IA consulte tus documentos

Añade un contenedor qdrant/qdrant a tu Compose. En n8n usa un flujo con Embeddings Ollama (nomic-embed-text) y el nodo Qdrant Vector Store: uno para cargar documentos y otro como herramienta del agente para consultarlos.

Respaldos

docker compose exec -T postgres pg_dump -U n8n n8n | gzip > n8n-$(date +%F).sql.gz
cp .env env-respaldo.txt   # guárdalo fuera del servidor

Respalda también el volumen n8n_data (método de la guía de Docker). Prueba restaurar de vez en cuando; un respaldo sin probar no es un respaldo.

Actualizar con seguridad

  1. Haz un respaldo.
  2. En la interfaz abre Settings → Migration Report (disponible desde la 2.39) para ver qué flujos afectaría la 3.0.
  3. Edita N8N_VERSION en .env y ejecuta docker compose pull && docker compose up -d.

Datos clave de la transición: no hay salto directo de 1.x a 3.x (pasa antes por 2.x), el soporte de 1.x termina el 31 de diciembre de 2026 y la 2.x recibirá correcciones de seguridad durante 12 meses tras la estable de la 3.0.

Buenas prácticas de seguridad

  • Mantén los puertos en 127.0.0.1 y expón solo el proxy HTTPS.
  • No dejes claves de API escritas en los nodos: usa siempre Credentials.
  • Fija la versión de la imagen. No uses latest en producción.

8. Solución de problemas

SíntomaCausa probable y solución
ECONNREFUSED ::1:11434n8n resuelve localhost como IPv6. Usa 127.0.0.1 o host.docker.internal.
No conecta a host.docker.internalFalta extra_hosts en Linux, o Ollama sigue escuchando solo en 127.0.0.1 (revisa OLLAMA_HOST).
Dice que no puede conectar a ollamaArranca con --profile ia y comprueba que ambos servicios estén en el mismo Compose.
Mismatching encryption keysLa clave del .env no coincide con la que usó n8n. Restaura la original; no la cambies en una instalación existente.
Aviso de “secure cookie” al abrir por IPEntra por localhost con túnel SSH o usa HTTPS.
El agente ignora las herramientasTu modelo no las soporta. Usa uno con etiqueta “tools” y el nodo Ollama Chat Model.
Respuestas muy lentasEl modelo es demasiado grande para tu RAM o CPU. Prueba uno más pequeño o usa GPU.
Error 429 con GeminiSuperaste el límite gratuito. Espera, activa reintentos o usa un modelo Flash más ligero.
