Antes de empezar

Lo mínimo que necesitas tener claro para que los laboratorios funcionen a la primera.

Qué usar en Packet Tracer

  • Switch 2960-24TT (capa 2): laboratorios 1 al 5 y 7 al 12. Tiene 24 puertos FastEthernet0/1-24 y 2 puertos GigabitEthernet0/1-2.
  • Switch multicapa 3650-24PS: solo el laboratorio 6.
  • Router 2911: laboratorios 5, 10 y 11.
  • PC y Server de la categoría End Devices.

Cómo está armado cada laboratorio

Objetivo, topología, pasos numerados (con los comandos listos para copiar con el botón Copiar), una sección para verificar y un reto. Al copiar, solo se copian los comandos: los prompts y las salidas se omiten.

Hábito clave. Después de cada laboratorio guarda la configuración en el equipo (copy running-config startup-config) y guarda el archivo .pkt (Ctrl+S). Son dos cosas distintas.

Configuración en ejecución vs. guardada

running-config vive en RAM: lo que escribes se aplica al instante, pero se pierde al reiniciar. startup-config vive en NVRAM: es lo que se carga al arrancar. Para guardar:

Switch# copy running-config startup-config
! atajo equivalente
Switch# write memory

Errores del CLI que verás mucho.

% Invalid input detected at '^' marker: el comando está mal escrito o estás en el modo equivocado. El ^ apunta al punto exacto del error.

% Incomplete command: falta un parámetro. Escribe ? al final para ver qué falta.

% Ambiguous command: la abreviatura coincide con varios comandos. Escribe más letras.

Lab 1

Configuración inicial

Tomar un switch sin configurar y dejarlo con nombre, contraseñas, banner, IP de gestión y configuración guardada.

Equipos1 switch 2960, 2 PCTiempo20 minAprenderáshostname, enable secret, líneas, SVI, guardar

Topología

 PC0 ---- cable de consola ----> [ SW1 ] <---- Fa0/1 (directo) ---- PC1
 (RS-232 -> Console)             IP gestión: 192.168.1.2/24         192.168.1.10/24

En PC1: Desktop > IP Configuration y escribe IP 192.168.1.10, máscara 255.255.255.0. En PC0 abre Desktop > Terminal (9600 baudios, valores por defecto) para practicar la consola real.

Paso a paso

  1. Mira el estado de fábrica

    Un switch nuevo ya funciona (todos los puertos están en la VLAN 1), pero sin nombre ni seguridad.

    Switch> enable
Switch# show running-config
Switch# show version
Switch# show ip interface brief
Switch# show vlan brief

  2. Ponle nombre y desactiva la búsqueda DNS

    no ip domain-lookup evita que el switch se quede 30 segundos "pensando" cuando escribes un comando mal.

    Switch# configure terminal
Switch(config)# hostname SW1
SW1(config)# no ip domain-lookup

  3. Protege el acceso con contraseñas

    enable secret protege el modo privilegiado (guardada con hash). Las líneas protegen la consola y el acceso remoto. service password-encryption cifra las contraseñas que quedan en texto plano.

    SW1(config)# enable secret Cisco123
SW1(config)# line console 0
SW1(config-line)# password cisco
SW1(config-line)# login
SW1(config-line)# logging synchronous
SW1(config-line)# exec-timeout 10 0
SW1(config-line)# exit
SW1(config)# line vty 0 15
SW1(config-line)# password cisco
SW1(config-line)# login
SW1(config-line)# exit
SW1(config)# service password-encryption

    logging synchronous evita que los mensajes del sistema te corten lo que estás escribiendo. exec-timeout 10 0 cierra la sesión tras 10 minutos sin actividad.

    Cuidado. service password-encryption usa cifrado tipo 7, que es reversible. Sirve para que nadie lea la contraseña por encima del hombro, no como seguridad real. Por eso en el Lab 2 pasaremos a usuarios con secret.

  4. Agrega un mensaje de advertencia (banner)

    El carácter # es el delimitador: el mensaje va entre dos #.

    SW1(config)# banner motd #Acceso solo para personal autorizado#

  5. Dale una IP de gestión (SVI)

    Un switch de capa 2 no necesita IP para conmutar, pero sí para administrarlo de forma remota. La IP se asigna a una interfaz virtual (SVI), no a un puerto físico.

    SW1(config)# interface vlan 1
SW1(config-if)# ip address 192.168.1.2 255.255.255.0
SW1(config-if)# no shutdown
SW1(config-if)# exit
SW1(config)# ip default-gateway 192.168.1.1

  6. Describe los puertos y guarda

    SW1(config)# interface fa0/1
SW1(config-if)# description PC1
SW1(config-if)# exit
SW1(config)# end
SW1# copy running-config startup-config
Destination filename [startup-config]?

    Pulsa Enter para aceptar el nombre por defecto.

Verifica

SW1# show running-config
SW1# show ip interface brief
SW1# show interfaces status
C:\> ping 192.168.1.2

Resultado esperado. Vlan1 aparece up/up con IP 192.168.1.2. Desde PC1, el ping responde (el primero puede fallar mientras se resuelve ARP: es normal). En show run las contraseñas de línea aparecen cifradas.

Reto. Cambia el banner y la IP de gestión, y haz reload sin guardar. Después de reiniciar, ¿qué cambios sobrevivieron? Repite guardando antes de reiniciar.

Lab 2

Acceso remoto seguro con SSH

Sustituir Telnet (texto plano) por SSH versión 2 con usuarios locales, y limitar los intentos fallidos.

Equiposel mismo switch del Lab 1 y PC1Tiempo15 minAprenderásclaves RSA, usuarios locales, transport input ssh

Topología

 PC1 (192.168.1.10) ---- Fa0/1 ---- [ SW1 ] 192.168.1.2/24
        |__ ssh -l admin 192.168.1.2 __|

Paso a paso

  1. Comprueba los requisitos

    SSH necesita un hostname distinto de "Switch" y un nombre de dominio. Las claves RSA se generan a partir de ambos.

    SW1# configure terminal
SW1(config)# ip domain-name lab.local

  2. Genera las claves RSA

    Cuando pregunte el tamaño, escribe 1024 (rápido en Packet Tracer). En equipos reales usa 2048 o más.

    SW1(config)# crypto key generate rsa
How many bits in the modulus [512]: 1024

  3. Crea el usuario y activa SSH v2

    SW1(config)# username admin privilege 15 secret Admin123
SW1(config)# ip ssh version 2
SW1(config)# line vty 0 15
SW1(config-line)# login local
SW1(config-line)# transport input ssh
SW1(config-line)# exec-timeout 5 0
SW1(config-line)# exit

    login local usa la base de usuarios del switch en vez de una contraseña de línea. transport input ssh rechaza Telnet. privilege 15 hace que el usuario entre directo en modo privilegiado.

  4. Bloquea los ataques de fuerza bruta

    Si hay 3 intentos fallidos en 60 segundos, el acceso remoto se bloquea 2 minutos.

    SW1(config)# login block-for 120 attempts 3 within 60
SW1(config)# end
SW1# copy running-config startup-config

    En Packet Tracer. Si tu versión no reconoce login block-for, sáltalo: el resto del laboratorio funciona igual.

Verifica

Desde PC1, abre Desktop > Command Prompt:

C:\> ssh -l admin 192.168.1.2
Password:
C:\> telnet 192.168.1.2
% Connection refused by remote host
SW1# show ip ssh
SW1# show ssh

Resultado esperado. SSH entra pidiendo la contraseña de admin; Telnet es rechazado. show ip ssh indica "SSH Enabled - version 2.0".

Reto. Crea un segundo usuario consulta sin privilegio 15. Al entrar por SSH verás SW1>, no SW1#. ¿Qué tienes que escribir para llegar a modo privilegiado y qué contraseña te pide?

Lab 3

VLANs y puertos de acceso

Separar la red en tres departamentos con VLANs, asignar puertos y mover la gestión a una VLAN dedicada.

Equipos1 switch 2960, 7 PCTiempo30 minAprenderásvlan, switchport access, SVI de gestión

Topología

                         [ SW1 ]
   Fa0/1  Fa0/2     Fa0/3  Fa0/4     Fa0/5  Fa0/6      Fa0/24
    |      |         |      |         |      |           |
  PC-V1  PC-V2     PC-C1  PC-C2     PC-T1  PC-T2     PC-Admin
     VLAN 10         VLAN 20          VLAN 30          VLAN 99
PCIPMáscaraPuerto
PC-V1 / PC-V2192.168.10.11 / .12255.255.255.0Fa0/1 / Fa0/2
PC-C1 / PC-C2192.168.20.11 / .12255.255.255.0Fa0/3 / Fa0/4
PC-T1 / PC-T2192.168.30.11 / .12255.255.255.0Fa0/5 / Fa0/6
PC-Admin192.168.99.10255.255.255.0Fa0/24

Por ahora deja el gateway de los PC vacío: lo agregaremos en el Lab 5.

Paso a paso

  1. Observa las VLANs que ya existen

    La VLAN 1 (default) y las 1002-1005 vienen de fábrica y no se pueden borrar. Todos los puertos empiezan en la VLAN 1.

    SW1# show vlan brief

  2. Crea y nombra las VLANs

    SW1# configure terminal
SW1(config)# vlan 10
SW1(config-vlan)# name Ventas
SW1(config-vlan)# exit
SW1(config)# vlan 20
SW1(config-vlan)# name Contabilidad
SW1(config-vlan)# exit
SW1(config)# vlan 30
SW1(config-vlan)# name TI
SW1(config-vlan)# exit
SW1(config)# vlan 99
SW1(config-vlan)# name Gestion
SW1(config-vlan)# exit
SW1(config)# vlan 999
SW1(config-vlan)# name Sin_Uso
SW1(config-vlan)# exit

  3. Asigna los puertos de acceso

    interface range configura varios puertos a la vez. Un puerto de acceso pertenece a una sola VLAN y envía las tramas sin etiqueta.

    SW1(config)# interface range fa0/1-2
SW1(config-if-range)# switchport mode access
SW1(config-if-range)# switchport access vlan 10
SW1(config-if-range)# exit
SW1(config)# interface range fa0/3-4
SW1(config-if-range)# switchport mode access
SW1(config-if-range)# switchport access vlan 20
SW1(config-if-range)# exit
SW1(config)# interface range fa0/5-6
SW1(config-if-range)# switchport mode access
SW1(config-if-range)# switchport access vlan 30
SW1(config-if-range)# exit
SW1(config)# interface fa0/24
SW1(config-if)# switchport mode access
SW1(config-if)# switchport access vlan 99
SW1(config-if)# exit

  4. Mueve la gestión de la VLAN 1 a la VLAN 99

    Buena práctica: la VLAN 1 no se usa para administrar. La SVI de la VLAN 99 solo se pone up si hay al menos un puerto activo en esa VLAN (por eso conectamos PC-Admin en Fa0/24).

    SW1(config)# interface vlan 1
SW1(config-if)# no ip address
SW1(config-if)# shutdown
SW1(config-if)# exit
SW1(config)# interface vlan 99
SW1(config-if)# ip address 192.168.99.2 255.255.255.0
SW1(config-if)# no shutdown
SW1(config-if)# exit
SW1(config)# ip default-gateway 192.168.99.1
SW1(config)# end
SW1# copy running-config startup-config

Verifica

SW1# show vlan brief
SW1# show interfaces fa0/1 switchport
SW1# show ip interface brief
C:\> ping 192.168.10.12
C:\> ping 192.168.20.11
C:\> ping 192.168.99.2

Resultado esperado. show vlan brief lista cada VLAN con sus puertos. PC-V1 hace ping a PC-V2 (misma VLAN) pero no a PC-C1: son redes distintas y aún no hay quien las enrute. PC-Admin hace ping a 192.168.99.2.

Trampa clásica. Si borras una VLAN con no vlan 10, los puertos asignados a ella no vuelven a la VLAN 1: quedan inactivos y desaparecen de show vlan brief. Reasígnalos a otra VLAN.

Reto. Cambia PC-V2 a la VLAN 20 con switchport access vlan 20 sin tocar su IP. ¿Con quién hace ping ahora y por qué falla con PC-V1?

Lab 4

Enlaces troncales (trunk)

Conectar dos switches para que las mismas VLANs existan en ambos, transportando varias VLANs por un solo cable.

Equipos2 switches 2960, 4 PCTiempo30 minAprenderástrunk 802.1Q, VLAN nativa, lista de VLANs permitidas, VTP

Topología

 PC-V1 (Fa0/1, VLAN10)                                   PC-V3 (Fa0/1, VLAN10)
 PC-C1 (Fa0/3, VLAN20)  [ SW1 ] Gi0/1 ===trunk=== Gi0/1 [ SW2 ]  PC-C3 (Fa0/3, VLAN20)
 PC-Admin (Fa0/24, V99)                                   SW2 gestión: 192.168.99.3

Agrega en SW2: PC-V3 con 192.168.10.13 (Fa0/1) y PC-C3 con 192.168.20.13 (Fa0/3). Conecta los switches con cable cruzado (o automático) en Gi0/1 de ambos.

Paso a paso

  1. Prepara SW2 con las mismas VLANs

    Una VLAN debe existir en ambos switches para que el tráfico atraviese el trunk.

    Switch> enable
Switch# configure terminal
Switch(config)# hostname SW2
SW2(config)# no ip domain-lookup
SW2(config)# enable secret Cisco123
SW2(config)# vlan 10
SW2(config-vlan)# name Ventas
SW2(config-vlan)# vlan 20
SW2(config-vlan)# name Contabilidad
SW2(config-vlan)# vlan 30
SW2(config-vlan)# name TI
SW2(config-vlan)# vlan 99
SW2(config-vlan)# name Gestion
SW2(config-vlan)# vlan 999
SW2(config-vlan)# name Sin_Uso
SW2(config-vlan)# exit
SW2(config)# interface fa0/1
SW2(config-if)# switchport mode access
SW2(config-if)# switchport access vlan 10
SW2(config-if)# interface fa0/3
SW2(config-if)# switchport mode access
SW2(config-if)# switchport access vlan 20
SW2(config-if)# exit
SW2(config)# interface vlan 99
SW2(config-if)# ip address 192.168.99.3 255.255.255.0
SW2(config-if)# no shutdown
SW2(config-if)# exit
SW2(config)# ip default-gateway 192.168.99.1

  2. Configura el trunk en ambos switches

    Repite este bloque en SW1 y en SW2. La VLAN nativa (la que viaja sin etiqueta) debe coincidir en los dos extremos; usamos la 99 en lugar de la 1 por seguridad.

    SW1(config)# interface g0/1
SW1(config-if)# switchport mode trunk
SW1(config-if)# switchport trunk native vlan 99
SW1(config-if)# switchport trunk allowed vlan 10,20,30,99
SW1(config-if)# description TRUNK a SW2
SW1(config-if)# end
SW1# copy running-config startup-config

    En Packet Tracer. El 2960 solo soporta 802.1Q, por eso no existe el comando switchport trunk encapsulation. Si lo ves en tutoriales, es para switches más antiguos o multicapa.

  3. Neutraliza VTP (recomendado mientras aprendes)

    VTP propaga VLANs entre switches automáticamente, pero un switch con un número de revisión más alto puede sobrescribir toda la base de VLANs de la red. En modo transparente ignora esos anuncios.

    SW1(config)# vtp mode transparent
SW2(config)# vtp mode transparent

Verifica

SW1# show interfaces trunk
SW1# show vlan brief
C:\> ping 192.168.10.13
C:\> ping 192.168.20.13
C:\> ping 192.168.99.3

Resultado esperado. show interfaces trunk muestra Gi0/1 en modo on, encapsulación 802.1q, nativa 99 y las VLANs 10,20,30,99 permitidas. PC-V1 hace ping a PC-V3 y PC-C1 a PC-C3 (misma VLAN, distinto switch). Entre VLANs distintas sigue sin haber ping.

Si algo falla, revisa en este orden. ¿Existe la VLAN en ambos switches? ¿La lista allowed incluye la VLAN? ¿La VLAN nativa coincide? Un desajuste genera mensajes NATIVE_VLAN_MISMATCH en la consola.

Reto. En SW1 ejecuta switchport trunk allowed vlan remove 20 y prueba el ping de VLAN 20 entre switches. Luego restáuralo con add 20. Ojo: allowed vlan 10,30 (sin add/remove) reemplaza toda la lista.

Lab 5

Enrutamiento entre VLANs (router-on-a-stick)

Lograr que las VLANs se comuniquen entre sí usando un solo cable trunk hacia un router con subinterfaces.

Equiposlo del Lab 4 + 1 router 2911Tiempo30 minAprenderássubinterfaces, encapsulation dot1Q, gateway, tracert

Topología

                                 R1
                              Gi0/0 (sin IP; subinterfaces .10 .20 .30 .99)
                                 |
                              Gi0/2 (trunk)
 PCs VLAN10/20/30 ----------- [ SW1 ] Gi0/1 ===trunk=== Gi0/1 [ SW2 ] ---- PCs VLAN10/20

Conecta R1 Gi0/0 a SW1 Gi0/2 con cable directo.

Paso a paso

  1. Convierte el puerto hacia el router en trunk (en SW1)

    SW1# configure terminal
SW1(config)# interface g0/2
SW1(config-if)# switchport mode trunk
SW1(config-if)# switchport trunk native vlan 99
SW1(config-if)# switchport trunk allowed vlan 10,20,30,99
SW1(config-if)# description TRUNK a R1
SW1(config-if)# exit

  2. Crea una subinterfaz por VLAN en el router

    La interfaz física solo se enciende; cada subinterfaz es el gateway de una VLAN. La convención es que el número de la subinterfaz coincida con el ID de la VLAN. En la 99, native le dice al router que esa VLAN viaja sin etiqueta.

    Router> enable
Router# configure terminal
Router(config)# hostname R1
R1(config)# interface g0/0
R1(config-if)# no shutdown
R1(config-if)# exit
R1(config)# interface g0/0.10
R1(config-subif)# description Gateway VLAN 10 Ventas
R1(config-subif)# encapsulation dot1Q 10
R1(config-subif)# ip address 192.168.10.1 255.255.255.0
R1(config-subif)# exit
R1(config)# interface g0/0.20
R1(config-subif)# description Gateway VLAN 20 Contabilidad
R1(config-subif)# encapsulation dot1Q 20
R1(config-subif)# ip address 192.168.20.1 255.255.255.0
R1(config-subif)# exit
R1(config)# interface g0/0.30
R1(config-subif)# description Gateway VLAN 30 TI
R1(config-subif)# encapsulation dot1Q 30
R1(config-subif)# ip address 192.168.30.1 255.255.255.0
R1(config-subif)# exit
R1(config)# interface g0/0.99
R1(config-subif)# description Gateway VLAN 99 Gestion
R1(config-subif)# encapsulation dot1Q 99 native
R1(config-subif)# ip address 192.168.99.1 255.255.255.0
R1(config-subif)# end
R1# copy running-config startup-config

  3. Configura el gateway en los PC

    En cada PC: IP Configuration > Default Gateway = la .1 de su red (por ejemplo 192.168.10.1 para VLAN 10). PC-Admin usa 192.168.99.1. Los switches ya tienen ip default-gateway 192.168.99.1 del Lab 3.

Verifica

R1# show ip interface brief
R1# show ip route
R1# show interfaces g0/0.10
C:\> ping 192.168.20.11
C:\> tracert 192.168.20.11

Resultado esperado. show ip route lista cuatro redes conectadas (C) y sus direcciones locales (L). El ping de VLAN 10 a VLAN 20 funciona, y tracert muestra un salto por 192.168.10.1 (el router). Los primeros paquetes pueden perderse mientras se llena la tabla ARP.

Lista de fallos típicos.

Olvidar no shutdown en la interfaz física. El trunk no permite alguna VLAN. El número de encapsulation dot1Q no coincide con la VLAN real. El PC tiene mal el gateway o la máscara. VLAN nativa distinta a cada lado.

Reto. Cambia encapsulation dot1Q 20 a 21 en la subinterfaz .20 y observa qué deja de funcionar. Usa show interfaces g0/0.20 para detectar el error y corrígelo.

Lab 6

Switch capa 3 (SVI)

Enrutar entre VLANs dentro del propio switch multicapa, sin router externo, y crear un puerto enrutado.

Equipos1 switch 3650-24PS (MLS1), 1 switch 2960, 4 PCTiempo25 minAprenderásip routing, SVI como gateway, no switchport

Topología

 PCs VLAN10/20/30 ---- [ SW1 ] Gi0/1 ===trunk=== Gi1/0/1 [ MLS1 ]  (VLANs 10,20,30,99 + SVIs)
                                                              |
                                                     Gi1/0/24 (puerto enrutado 10.0.0.1/30)

Hazlo en un archivo nuevo, o desconecta R1 para que no haya dos gateways compitiendo. Los nombres de puerto del 3650 son del tipo Gi1/0/1.

Paso a paso

  1. Crea las VLANs en el switch multicapa

    Las SVI solo se activan si la VLAN existe en el switch.

    Switch> enable
Switch# configure terminal
Switch(config)# hostname MLS1
MLS1(config)# vlan 10
MLS1(config-vlan)# name Ventas
MLS1(config-vlan)# vlan 20
MLS1(config-vlan)# name Contabilidad
MLS1(config-vlan)# vlan 30
MLS1(config-vlan)# name TI
MLS1(config-vlan)# vlan 99
MLS1(config-vlan)# name Gestion
MLS1(config-vlan)# exit

  2. Enlace trunk hacia SW1

    MLS1(config)# interface g1/0/1
MLS1(config-if)# switchport mode trunk
MLS1(config-if)# switchport trunk native vlan 99
MLS1(config-if)# switchport trunk allowed vlan 10,20,30,99
MLS1(config-if)# exit

Lab 7

Seguridad de puertos

Impedir que un dispositivo desconocido use un puerto, apagar lo que no se usa y cerrar puertas típicas de ataque en el switch.

EquiposSW1 del Lab 3 (o Lab 5), varios PC y un PC extra "intruso"Tiempo30 minAprenderásport-security, sticky MAC, err-disabled, puertos sin uso, DTP

Topología

 PC-V1 (Fa0/1)  PC-V2 (Fa0/2) ... PC-T2 (Fa0/6)        Fa0/7-23: sin uso -> VLAN 999 + shutdown
                       \  |  /                          Fa0/24: PC-Admin (VLAN 99)
                        [ SW1 ] Gi0/1 = trunk, Gi0/2 = trunk / router

Paso a paso

  1. Activa port-security en los puertos de acceso

    El puerto debe estar en modo access fijo antes de activar la seguridad. Con sticky, el switch aprende la MAC del primer dispositivo que envía tráfico y la guarda en la configuración.

    SW1# configure terminal

SW1(config-if-range)# switchport port-security maximum 1

SW1(config-if-range)# switchport port-security violation shutdown
SW1(config-if-range)# exit

    Haz un ping desde cada PC para que el switch aprenda sus MAC.

    Modo de violaciónQué hace al detectar una MAC no permitida
    protectDescarta las tramas extra. Sin aviso ni registro
    restrictDescarta las tramas y genera mensajes de log y contador de violaciones
    shutdown (por defecto)Deshabilita el puerto (err-disabled). Es el más seguro

  2. Comprueba lo que aprendió

SW1# show port-security interface fa0/1
SW1# show port-security address
SW1# show running-config interface fa0/1

    En la configuración del puerto verás una línea switchport port-security mac-address sticky <MAC> agregada sola.

  3. Provoca una violación a propósito

    Desconecta PC-V1 de Fa0/1 y conecta en su lugar el PC intruso (otra MAC). Haz un ping desde él. El puerto se pondrá en rojo.

SW1(config-if)# end

    En Packet Tracer. Si clear port-security sticky no existe en tu versión, quita sticky del puerto y vuelve a ponerlo para olvidar la MAC guardada.

Lab 8

Spanning Tree (STP)

Entender cómo el switch evita bucles, elegir tú mismo el root bridge y proteger los puertos de usuario.

Equipos3 switches 2960 en triángulo, 2 PCTiempo35 minAprenderásroot bridge, roles de puerto, Rapid-PVST, PortFast, BPDU Guard

Topología

                    [ SW1 ]  (será el root)
              Gi0/1 /         \ Gi0/2
                   /           \
            Gi0/1 /             \ Gi0/2
             [ SW2 ]-----------[ SW3 ]
                    Fa0/1   Fa0/1

 PC-V1 en SW2 Fa0/2 (VLAN 10)        PC-V3 en SW3 Fa0/2 (VLAN 10)
 192.168.10.11                       192.168.10.13

Conecta en triángulo: SW1 Gi0/1 con SW2 Gi0/1, SW1 Gi0/2 con SW3 Gi0/2, y SW2 con SW3 por Fa0/1 en ambos. Configura trunk en los tres enlaces como en el Lab 4, crea las VLANs 10 y 99 en los tres switches y pon Fa0/2 de SW2 y SW3 como acceso en VLAN 10.

Paso a paso

  1. Observa quién es el root bridge

    STP elige como root al switch con menor prioridad (por defecto 32768 + ID de VLAN); si hay empate, gana la MAC más baja. Los demás calculan el camino de menor costo hacia él y bloquean el puerto que cierra el bucle.

    SW1# show spanning-tree vlan 10
SW2# show spanning-tree vlan 10
SW3# show spanning-tree vlan 10

    Busca "This bridge is the root" y fíjate en los roles: Root (mejor camino al root), Desg (designado) y Altn / BLK (bloqueado). Anota qué puerto quedó bloqueado.

  2. Elige tú el root bridge

    Que sea el switch central (aquí SW1), no el que casualmente tenga la MAC más baja. Deja a SW2 como respaldo.

    SW1(config)# spanning-tree vlan 1,10,20,30,99 root primary
SW2(config)# spanning-tree vlan 1,10,20,30,99 root secondary

    root primary baja la prioridad automáticamente por debajo de la actual. Alternativa manual: spanning-tree vlan 10 priority 4096 (siempre múltiplos de 4096).

  3. Cambia a Rapid-PVST

    El STP clásico tarda hasta 50 segundos en reconverger. Rapid-PVST lo hace en pocos segundos. Aplícalo en los tres switches.

    SW1(config)# spanning-tree mode rapid-pvst
SW2(config)# spanning-tree mode rapid-pvst
SW3(config)# spanning-tree mode rapid-pvst

  4. Protege los puertos de usuario

    portfast pone el puerto en reenvío de inmediato (sin esperar la convergencia). bpduguard lo apaga si alguien conecta un switch ahí, evitando que altere la topología.

    SW2(config)# interface range fa0/2-6
SW2(config-if-range)# spanning-tree portfast
SW2(config-if-range)# spanning-tree bpduguard enable
SW2(config-if-range)# end
SW2# copy running-config startup-config

    Nunca actives PortFast en enlaces entre switches; solo en puertos hacia PC, servidores o impresoras.

  5. Rompe un enlace y mira cómo se recupera

    En PC-V1 abre el Command Prompt y deja un ping continuo. Luego apaga el enlace activo hacia el root.

    C:\> ping -t 192.168.10.13
SW2(config)# interface g0/1
SW2(config-if)# shutdown
! espera unos segundos y mira el ping; luego restaura el enlace
SW2(config-if)# no shutdown

    Observa cuántos paquetes se pierden hasta que el puerto que estaba bloqueado pasa a reenviar.

Verifica

SW1# show spanning-tree summary
SW1# show spanning-tree vlan 10
SW2# show spanning-tree interface fa0/2 detail

Resultado esperado. SW1 dice "This bridge is the root" en todas las VLANs; el modo es rapid-pvst; hay exactamente un puerto bloqueado en el triángulo. Los puertos de PC aparecen con la marca P2p Edge.

Lab 9

EtherChannel

Juntar dos cables entre switches como un solo enlace lógico con más ancho de banda y redundancia, sin que STP bloquee uno.

Equipos2 switches 2960, 2 PCTiempo25 minAprenderásLACP, port-channel, verificación con show etherchannel

Topología

 PC-V1 -- [ SW1 ] Gi0/1 =========== Gi0/1 [ SW2 ] -- PC-V3
                  Gi0/2 =========== Gi0/2
                        Port-channel 1 (LACP)

Hazlo en un archivo nuevo con SW1 y SW2 (o quita otras conexiones que usen Gi0/1-2). Ya deben tener las VLANs 10, 20, 30 y 99.

Paso a paso

  1. Agrupa los puertos físicos en un canal LACP

    Repite en SW2. active significa que el puerto inicia la negociación LACP. Apagar los puertos antes evita que STP los bloquee mientras configuras.

    SW1# configure terminal
SW1(config)# interface range g0/1-2
SW1(config-if-range)# shutdown
SW1(config-if-range)# channel-group 1 mode active
SW1(config-if-range)# no shutdown
SW1(config-if-range)# exit

  2. Configura el trunk en el port-channel, no en los puertos

    Lo que configures en la interfaz lógica se aplica a todos los miembros. Repite en SW2 con la misma configuración.

    SW1(config)# interface port-channel 1
SW1(config-if)# switchport mode trunk
SW1(config-if)# switchport trunk native vlan 99
SW1(config-if)# switchport trunk allowed vlan 10,20,30,99
SW1(config-if)# end
SW1# copy running-config startup-config

Cómo se combinan los modos

ProtocoloModosSe forma el canal si...
LACP (estándar IEEE)active / passiveactive-active o active-passive. Nunca passive-passive
PAgP (propietario Cisco)desirable / autodesirable-desirable o desirable-auto. Nunca auto-auto
Estáticoonon en ambos lados. No se mezcla con LACP ni PAgP

Verifica

SW1# show etherchannel summary
SW1# show interfaces trunk
SW1# show spanning-tree vlan 10
C:\> ping -t 192.168.10.13

Resultado esperado. En show etherchannel summary ves Po1(SU) (S = capa 2, U = en uso) y ambos puertos con (P) (en el canal). STP trata el Po1 como un solo enlace: ningún puerto bloqueado.

Si un puerto sale con (s) o (I). La configuración de los miembros no coincide: velocidad, dúplex, modo trunk, VLAN nativa o lista de VLANs distintos entre los dos puertos o entre los dos switches.

Reto. Con el ping continuo activo, apaga Gi0/1 en SW1. ¿Cuántos paquetes se pierden? Vuelve a encenderlo y confirma en show etherchannel summary que regresa al canal.

DHCP y DHCP Snooping

Repartir direcciones IP automáticamente a cada VLAN y evitar que un servidor DHCP falso (rogue) engañe a los PC.

R1(config)# ip dhcp excluded-address 192.168.20.1 192.168.20.10

R1(dhcp-config)# exit

R1(dhcp-config)# network 192.168.20.0 255.255.255.0
R1(dhcp-config)# default-router 192.168.20.1
R1(dhcp-config)# dns-server 8.8.8.8
R1(dhcp-config)# exit

R1(dhcp-config)# network 192.168.30.0 255.255.255.0

    En cada PC: Desktop > IP Configuration > DHCP. Si ya tenían IP fija, cámbiala a DHCP. Debe aparecer una IP dentro de su VLAN.

C:\> ipconfig
R1# show ip dhcp binding
R1# show ip dhcp pool

  3. Activa DHCP Snooping en los switches

    Snooping actúa como firewall de DHCP: solo los puertos marcados trust pueden responder con ofertas (Offer/Ack). Marca como confiables los puertos hacia el router y hacia el otro switch. Repite en SW2 con sus puertos troncales.

ACLs y control de administración

Decidir qué VLAN puede hablar con cuál, y permitir que solo la VLAN de gestión administre el switch por SSH.

Equipostopología del Lab 5 con SSH del Lab 2 activoTiempo30 minAprenderásACL extendida nombrada, access-group, access-class, contadores

Topología

 VLAN 10 Ventas ---\
 VLAN 20 Contab.  ---[ SW1 ]---trunk---[ R1 ]   ACL VENTAS-IN en R1 Gi0/0.10 (entrada)
 VLAN 30 TI      ---/                            ACL ADMIN-SSH en las líneas vty de SW1
 VLAN 99 PC-Admin -/

Regla práctica. Las ACL extendidas se colocan lo más cerca posible del origen del tráfico; las estándar (solo filtran por IP origen), lo más cerca del destino. Al final de toda ACL hay un deny any implícito.

Paso a paso

  1. Bloquea Ventas → TI, pero permite todo lo demás

    El orden importa: la primera regla que coincide se aplica. Sin el permit ip any any final, el deny implícito bloquearía todo.

    R1# configure terminal
R1(config)# ip access-list extended VENTAS-IN
R1(config-ext-nacl)# remark Ventas no puede llegar a TI
R1(config-ext-nacl)# deny ip 192.168.10.0 0.0.0.255 192.168.30.0 0.0.0.255
R1(config-ext-nacl)# permit ip any any
R1(config-ext-nacl)# exit
R1(config)# interface g0/0.10
R1(config-subif)# ip access-group VENTAS-IN in
R1(config-subif)# end

    Se usa la máscara wildcard (0.0.0.255), que es la inversa de la máscara de subred (255.255.255.0).

  2. Permite SSH solo desde la VLAN de gestión

    Una ACL en las líneas vty (con access-class) filtra quién puede conectarse al switch, sin afectar el tráfico normal.

    SW1# configure terminal
SW1(config)# ip access-list standard ADMIN-SSH
SW1(config-std-nacl)# permit 192.168.99.0 0.0.0.255
SW1(config-std-nacl)# exit
SW1(config)# line vty 0 15
SW1(config-line)# access-class ADMIN-SSH in
SW1(config-line)# end
SW1# copy running-config startup-config

Verifica

C:\> ping 192.168.20.11
C:\> ping 192.168.30.11
R1# show access-lists
R1# show ip interface g0/0.10
C:\> ssh -l admin 192.168.99.2

Resultado esperado. Desde Ventas, el ping a Contabilidad responde, pero el ping a TI falla con "Destination host unreachable" (lo devuelve el router). show access-lists muestra contadores (matches) que suben en la regla deny. El SSH a 192.168.99.2 funciona desde PC-Admin y falla desde un PC de otra VLAN.

Cuidado al probar. Una ACL mal aplicada en la interfaz por la que te administras puede dejarte fuera. Practica con la consola de Packet Tracer a mano para poder deshacerlo (no ip access-group VENTAS-IN in).

Reto. Modifica la ACL para que Ventas sí pueda hacer ping a TI pero no pueda hacer SSH (puerto 22) a nada de esa red. Pista: permit icmp ... antes del deny tcp ... eq 22.

Proyecto final: integra todo

Construye una red pequeña desde cero usando lo aprendido, sin mirar los laboratorios (o mirándolos solo para consultar).

                       R1  (DHCP + ACL + gateway por subinterfaces)
                        |
                     [ SW1 ] root bridge
             Po1 (2 cables) /   \ Gi0/2
                        [ SW2 ]--------[ SW3 ]
   VLAN 10 y 20 en SW2 y SW3, VLAN 30 solo en SW3, VLAN 99 en los tres

Requisitos

  • Nombres, enable secret, banner, SSH v2 con usuario local y IP de gestión en VLAN 99 en los tres switches.
  • VLANs 10, 20, 30, 99 y 999. Trunks con VLAN nativa 99 y lista de VLANs permitidas.
  • SW1 y SW2 unidos por un EtherChannel LACP de dos enlaces.
  • SW1 es root primary y SW2 root secondary. Rapid-PVST en todos. PortFast y BPDU Guard en puertos de PC.
  • Port-security con sticky (máximo 1 MAC) en los puertos de usuario. Puertos libres en VLAN 999 y apagados.
  • R1 con subinterfaces como gateway y pools DHCP para las VLANs 10, 20 y 30. DHCP snooping en los switches.
  • ACL: Ventas (VLAN 10) no llega a TI (VLAN 30). Solo la VLAN 99 puede hacer SSH a los switches.
  • Respaldo de todas las configuraciones en un servidor TFTP.

Cómo saber que quedó bien

  • Cada PC obtiene IP por DHCP en su VLAN y hace ping a su gateway.
  • Ventas y Contabilidad se comunican; Ventas no llega a TI.
  • Apagas un enlace del EtherChannel y el ping continuo casi no se corta.
  • Un PC intruso en un puerto de usuario lo deja en err-disabled.
  • Desde una VLAN de usuario no puedes entrar por SSH a los switches; desde PC-Admin sí.

Cuando lo logres, ya tienes las bases de un CCNA en switching. Los siguientes temas naturales son OSPF, NAT, VLAN de voz y redes inalámbricas.
