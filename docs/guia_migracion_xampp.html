Idea central: nunca instales encima de la versión vieja. Respalda, aparta la carpeta antigua, instala limpio y restaura solo lo tuyo (sitios, bases de datos y ajustes).

Los comandos asumen Windows, XAMPP en C:\xampp y respaldos en C:\backup_xampp. Ajusta las rutas si las tuyas difieren. La versión de destino es la más reciente que aparezca en apachefriends.org; elige la serie de PHP que soporten tus proyectos. Marca los pasos según avances; el progreso queda guardado en este navegador.

1Antes de empezar

Documenta cómo está todo hoy para poder compararlo después.

  • mkdir C:\backup_xampp
C:\xampp\php\php.exe -v > C:\backup_xampp\versiones.txt
C:\xampp\apache\bin\httpd.exe -v >> C:\backup_xampp\versiones.txt
C:\xampp\mysql\bin\mysql.exe --version >> C:\backup_xampp\versiones.txt
C:\xampp\php\php.exe -m > C:\backup_xampp\modulos_php.txt
  • certutil -hashfile C:\ruta\xampp-installer.exe SHA256

    Compara con el hash que muestre la página de descarga. Si publican MD5 o SHA1, cambia el algoritmo en el comando.

2Respaldar bases de datos

Con MySQL/MariaDB encendido y Apache detenido, para que nada escriba durante el volcado.

  • cd C:\xampp\mysql\bin
mysqldump.exe -u root -p --databases bd1 bd2 --routines --triggers --events --result-file=C:\backup_xampp\bd_usuario.sql

    Usa --result-file, no >. En PowerShell el redireccionamiento guarda el archivo en UTF-16 y el volcado queda inservible al importar.

  • mysqldump.exe -u root -p --all-databases --routines --triggers --events --result-file=C:\backup_xampp\bd_todas.sql
  • mysql.exe -u root -p -e "SELECT user,host FROM mysql.user;"
mysql.exe -u root -p -e "SHOW GRANTS FOR 'usuario'@'localhost';"
  • powershell -c "Get-Content C:\backup_xampp\bd_usuario.sql -Tail 2"
  • robocopy C:\xampp\mysql\data C:\backup_xampp\mysql_data /E /R:1 /W:1

    No copies esta carpeta a la instalación nueva. Si cambia la versión mayor de MariaDB, los archivos internos son incompatibles y MySQL deja de arrancar. Se restaura con los volcados .sql.

3Respaldar sitios y configuración

  • robocopy C:\xampp\htdocs C:\backup_xampp\htdocs /E /R:1 /W:1
  • mkdir C:\backup_xampp\config
robocopy C:\xampp\apache\conf C:\backup_xampp\config\apache_conf /E
copy C:\xampp\php\php.ini C:\backup_xampp\config\
copy C:\xampp\mysql\bin\my.ini C:\backup_xampp\config\
copy C:\xampp\phpMyAdmin\config.inc.php C:\backup_xampp\config\
copy C:\xampp\sendmail\sendmail.ini C:\backup_xampp\config\
copy C:\xampp\xampp-control.ini C:\backup_xampp\config\
copy C:\Windows\System32\drivers\etc\hosts C:\backup_xampp\config\hosts.txt

    La carpeta apache\conf ya incluye extra\httpd-vhosts.conf y los certificados de ssl.crt y ssl.key.

4Apartar la versión vieja

Renombrar la carpeta es el mejor respaldo: la reversa tarda un minuto.

  • robocopy C:\xampp C:\backup_xampp\xampp_completo /E /R:1 /W:1
  • ren C:\xampp xampp_old

    Si Windows dice que está en uso, cierra editores y terminales abiertos en esa carpeta, o reinicia el equipo y vuelve a intentarlo.

5Instalar la versión nueva

  • Si un puerto está ocupado, mira la sección de problemas comunes al final.

  • C:\xampp\php\php.exe -v
C:\xampp\mysql\bin\mysql.exe --version

6Restaurar sitios y bases de datos

  • robocopy C:\backup_xampp\htdocs C:\xampp\htdocs /E /R:1 /W:1

    Si no quieres pisar el dashboard ni el index.php de la versión nueva, copia solo las carpetas de tus proyectos.

  • cd C:\xampp\mysql\bin
mysql.exe -u root -p -e "source C:/backup_xampp/bd_usuario.sql"

    No importes bd_todas.sql en la instalación nueva. Trae las tablas internas del sistema (mysql) de la versión anterior y puede romperla. Sirve solo como archivo.

  • CREATE USER 'usuario'@'localhost' IDENTIFIED BY 'clave';
GRANT ALL PRIVILEGES ON bd1.* TO 'usuario'@'localhost';
FLUSH PRIVILEGES;
  • mysql.exe -u root -p -e "SELECT table_schema, COUNT(*) AS tablas FROM information_schema.tables GROUP BY table_schema;"

7Reaplicar configuración

No sobrescribas los archivos nuevos con los viejos: compáralos y traslada solo tus cambios (WinMerge, Notepad++ con Compare, o fc).

8Verificar

  • C:\xampp\apache\logs\error.log
C:\xampp\php\logs\php_error_log
C:\xampp\mysql\data\mysql_error.log

9Reversa y limpieza

  • ren C:\xampp xampp_nueva_fallida
ren C:\xampp_old xampp

    Con la vieja de vuelta en su sitio, inicia los módulos desde su panel. Si MySQL no abre, los volcados .sql del paso 2 siguen siendo tu respaldo.

Apache no inicia: puerto 80 o 443 ocupado
Busca el proceso con netstat -ano | findstr :80. Suelen ser IIS, el servicio «World Wide Web Publishing», Skype o VMware. Detenlo o cambia Listen en httpd.conf (y el puerto SSL en httpd-ssl.conf).
MySQL no inicia
Lee mysql\data\mysql_error.log. Causas típicas: puerto 3306 ocupado por otra instancia, o carpeta data copiada desde otra versión. Si es lo segundo, borra los datos de la instalación nueva, reinstala limpio y restaura con los .sql.
Access denied al abrir phpMyAdmin o desde un proyecto
La contraseña de root no coincide con config.inc.php o con el archivo de conexión del proyecto.
Unable to load dynamic library
La DLL no corresponde a la versión de PHP, a su arquitectura o a TS/NTS. Descarga la correcta.
Error de collation o sintaxis al importar un volcado
El volcado viene de una versión de servidor más nueva que la de destino, o el archivo se guardó en UTF-16 (ver aviso del paso 2). Vuelve a generarlo con --result-file.
Páginas con errores o avisos nuevos tras el cambio de PHP
Revisa php_error_log: casi siempre son funciones eliminadas, parámetros nulos en funciones que ya no los aceptan o propiedades dinámicas obsoletas. Actualiza el código o las librerías.
