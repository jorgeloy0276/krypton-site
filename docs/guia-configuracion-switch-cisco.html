Guía configuración Switch CISCO

Lab 0 · Preparación y modos CLI

Objetivo: conocer el entorno y moverte por los modos del IOS.

Topología: 1 PC + 1 Switch 2960. Cable consola (celeste) de la PC (RS232) al puerto Console del switch. En la PC: Desktop → Terminal (9600, 8, None, 1, None).
ModoPromptCómo entrar
UsuarioSwitch>Por defecto
PrivilegiadoSwitch#enable
Configuración globalSwitch(config)#configure terminal
InterfazSwitch(config-if)#interface fa0/1
LíneaSwitch(config-line)#line console 0
Switch> enable
Switch# configure terminal
Switch(config)# exit        ! sube un nivel
Switch(config)# end         ! vuelve directo a #  (o Ctrl+Z)
Switch# show version
Switch# show running-config
Switch# show ip interface brief
Trucos: Tab autocompleta, ? muestra ayuda, no deshace un comando, y do show ... ejecuta show dentro de config. Abreviaturas válidas: conf t, int fa0/1, sh run.

Lab 1 · Configuración básica inicial

Objetivo: dejar el switch con nombre, contraseñas, banner y administración IP.

Topología: PC0 ── Switch0 (SW1). PC0: IP 192.168.1.10/24. SW1 usará 192.168.1.2/24 en la VLAN 1 (gestión).
enable
configure terminal
hostname SW1
no ip domain-lookup                 ! evita esperas por errores de tipeo
banner motd # Acceso solo autorizado #

! Contraseñas
enable secret Cisco123              ! cifrada (MD5), usa esta y no "enable password"
service password-encryption         ! cifra las demás contraseñas

line console 0
 password cisco
 login
 logging synchronous                ! evita que los logs interrumpan lo que escribes
 exec-timeout 10 0
exit
line vty 0 15
 password cisco
 login
exit

! IP de administración
interface vlan 1
 ip address 192.168.1.2 255.255.255.0
 no shutdown
exit
ip default-gateway 192.168.1.1
end
copy running-config startup-config  ! GUARDAR (o: write memory)

Verificación

show running-config
show ip interface brief
ping 192.168.1.10                   ! desde el switch hacia la PC
! Desde la PC: Command Prompt → ping 192.168.1.2
Si no guardas con copy run start, al reiniciar pierdes todo. En Packet Tracer también puedes usar el botón «Save».

Lab 2 · Acceso remoto seguro con SSH

Objetivo: sustituir Telnet (texto plano) por SSH con usuarios locales.

Topología: igual al Lab 1. Cable cruzado o directo (Packet Tracer lo acepta) PC0 ↔ SW1.
configure terminal
ip domain-name curso.local
username admin secret Admin123
crypto key generate rsa             ! elige 1024 o 2048 bits
ip ssh version 2

line vty 0 15
 login local                        ! usa la base local de usuarios
 transport input ssh                ! bloquea Telnet
 exec-timeout 5 0
end

Verificación

show ip ssh
show ssh
! Desde PC0 → Command Prompt:
ssh -l admin 192.168.1.2
Requisito: el switch debe tener hostname y domain-name configurados antes de generar las claves RSA.

Lab 3 · Interfaces: descripción, velocidad y rangos

Objetivo: configurar puertos y leer su estado.

Topología: SW1 con PC0 en Fa0/1, PC1 en Fa0/2 y un servidor en Fa0/3.
configure terminal
interface fa0/1
 description PC0-Ventas
 speed 100
 duplex full
 no shutdown
exit

interface range fa0/1 - 3           ! configura varios puertos a la vez
 description Puertos de usuarios
exit

interface range fa0/10 - 24
 shutdown                           ! apagar puertos sin uso
end

Verificación

show interfaces status
show interfaces fa0/1
show ip interface brief
show mac address-table
Estados: up/up = funciona; up/down = problema de capa 2; administratively down = tiene shutdown; down/down = cable desconectado.

Lab 4 · VLANs y puertos de acceso

Objetivo: segmentar la red en VLAN 10 (Ventas), 20 (IT) y 99 (Gestión).

Topología: SW1 con PC0 (Fa0/1) y PC1 (Fa0/2) en VLAN 10; PC2 (Fa0/3) y PC3 (Fa0/4) en VLAN 20. IPs: 192.168.10.x/24 y 192.168.20.x/24.
configure terminal
vlan 10
 name Ventas
vlan 20
 name IT
vlan 99
 name Gestion
exit

interface range fa0/1 - 2
 switchport mode access
 switchport access vlan 10
exit
interface range fa0/3 - 4
 switchport mode access
 switchport access vlan 20
exit

! Mover la gestión a la VLAN 99
interface vlan 99
 ip address 192.168.99.2 255.255.255.0
 no shutdown
end

Verificación

show vlan brief
show interfaces fa0/1 switchport
! PC0 ↔ PC1 hacen ping (misma VLAN). PC0 ↔ PC2 NO (otra VLAN) hasta el Lab 6.
Si eliminas una VLAN con no vlan 10, los puertos asignados quedan inactivos: reasígnalos antes.

Lab 5 · Troncales 802.1Q y VLAN nativa

Objetivo: transportar varias VLAN entre dos switches por un solo enlace.

Topología: SW1 Gi0/1 ── Gi0/1 SW2. En ambos, crea VLAN 10, 20 y 99. PC0 y PC2 en SW1 (VLAN 10 y 20); PC1 y PC3 en SW2 (VLAN 10 y 20).
! En SW1 y SW2 (mismo bloque)
configure terminal
interface gi0/1
 switchport mode trunk
 switchport trunk native vlan 99
 switchport trunk allowed vlan 10,20,99
 switchport nonegotiate             ! desactiva DTP
end

Verificación

show interfaces trunk
show interfaces gi0/1 switchport
! PC0 (SW1, VLAN 10) hace ping a PC1 (SW2, VLAN 10) → debe funcionar
La VLAN nativa debe coincidir en ambos extremos o verás avisos de CDP. Evita usar la VLAN 1 como nativa por seguridad.

Lab 6 · Enrutamiento entre VLAN

Objetivo: que VLAN 10 y VLAN 20 se comuniquen. Dos métodos.

Método A · Router-on-a-stick

Topología: Router 2911 Gi0/0 ── Fa0/24 SW1 (troncal). PCs: gateway 192.168.10.1 (VLAN 10) y 192.168.20.1 (VLAN 20).
! En SW1
interface fa0/24
 switchport mode trunk

! En el Router
interface gi0/0
 no shutdown
interface gi0/0.10
 encapsulation dot1Q 10
 ip address 192.168.10.1 255.255.255.0
interface gi0/0.20
 encapsulation dot1Q 20
 ip address 192.168.20.1 255.255.255.0
interface gi0/0.99
 encapsulation dot1Q 99 native
 ip address 192.168.99.1 255.255.255.0

Método B · Switch capa 3 (3560 / 3650)

ip routing
interface vlan 10
 ip address 192.168.10.1 255.255.255.0
interface vlan 20
 ip address 192.168.20.1 255.255.255.0
! Puerto hacia otro router sin switchport:
interface gi0/24
 no switchport
 ip address 10.0.0.2 255.255.255.252
! Ruta por defecto
ip route 0.0.0.0 0.0.0.0 10.0.0.1

Verificación

show ip route
show ip interface brief
! PC de VLAN 10 → ping a PC de VLAN 20 (con gateway configurado en cada PC)

Lab 7 · VTP (propagación de VLAN)

Objetivo: crear las VLAN en un solo switch y replicarlas a los demás.

Topología: SW1 (servidor) ── troncal ── SW2 (cliente) ── troncal ── SW3 (cliente).
! SW1 (servidor)
vtp mode server
vtp domain CURSO
vtp password vtp123
vtp version 2
vlan 30
 name Soporte

! SW2 y SW3
vtp mode client
vtp domain CURSO
vtp password vtp123

Verificación

show vtp status
show vlan brief                     ! en los clientes debe aparecer la VLAN 30
Cuidado: un switch nuevo con revision number mayor puede borrar las VLAN de toda la red. Muchos administradores usan vtp mode transparent o off. Los clientes no pueden crear VLAN.

Lab 8 · Spanning Tree (STP / RSTP)

Objetivo: evitar bucles, elegir el root bridge y proteger los puertos.

Topología: triángulo de 3 switches (SW1, SW2, SW3) conectados entre sí con troncales. Debe haber un enlace redundante.
! Modo rápido
spanning-tree mode rapid-pvst

! Elegir root bridge
spanning-tree vlan 1,10,20 root primary        ! en SW1
spanning-tree vlan 1,10,20 root secondary      ! en SW2
! Alternativa manual: spanning-tree vlan 10 priority 4096

! Puertos de acceso (PCs)
interface range fa0/1 - 4
 spanning-tree portfast             ! pasa a forwarding de inmediato
 spanning-tree bpduguard enable     ! apaga el puerto si llega un BPDU
exit
! Global: spanning-tree portfast default / bpduguard default
! Evitar que un puerto de acceso sea elegido root
spanning-tree guard root            ! en interfaces que no deben ser root

Verificación

show spanning-tree
show spanning-tree vlan 10
show spanning-tree summary
En show spanning-tree busca «This bridge is the root» y los roles: Root, Desg (designado) y Altn (bloqueado). Nunca actives PortFast en enlaces entre switches.

Lab 9 · EtherChannel (agregación de enlaces)

Objetivo: unir 2 o más cables en un enlace lógico con más ancho de banda y redundancia.

Topología: SW1 Gi0/1 y Gi0/2 ── SW2 Gi0/1 y Gi0/2 (dos cables entre ambos).
! En SW1 y SW2
interface range gi0/1 - 2
 channel-group 1 mode active        ! LACP (estándar). PAgP (Cisco): desirable
exit
interface port-channel 1
 switchport mode trunk
 switchport trunk native vlan 99

Verificación

show etherchannel summary           ! debe verse Po1(SU) con Gi0/1(P) Gi0/2(P)
show interfaces port-channel 1
Modos compatibles: active↔active/passive (LACP), desirable↔desirable/auto (PAgP), on↔on. Velocidad, duplex y VLAN deben coincidir en todos los puertos del grupo.

Lab 10 · Port Security

Objetivo: limitar qué dispositivos pueden usar un puerto.

Topología: SW1 con PC0 en Fa0/1. Para probar, conecta después un segundo equipo (laptop) a ese puerto.
interface fa0/1
 switchport mode access
 switchport port-security
 switchport port-security maximum 1
 switchport port-security mac-address sticky     ! aprende la MAC conectada
 switchport port-security violation shutdown     ! o restrict / protect
exit

! Recuperar un puerto en err-disabled
interface fa0/1
 shutdown
 no shutdown

Verificación

show port-security
show port-security interface fa0/1
show interfaces status err-disabled
! Recuperación automática:
errdisable recovery cause psecure-violation
errdisable recovery interval 60
ViolaciónEfecto
protectDescarta tráfico, sin aviso
restrictDescarta y genera log/contador
shutdownPuerto en err-disabled (por defecto)

Lab 11 · Seguridad de capa 2 avanzada

Objetivo: mitigar ataques típicos (DHCP spoofing, ARP spoofing, VLAN hopping, tormentas).

11.1 Buenas prácticas básicas

! Puertos sin uso: apagados y en una VLAN «agujero negro»
vlan 999
 name BLACKHOLE
interface range fa0/10 - 24
 switchport mode access
 switchport access vlan 999
 shutdown

! Anti VLAN hopping
interface range fa0/1 - 9
 switchport mode access
 switchport nonegotiate
! VLAN nativa distinta de la 1 en troncales (ver Lab 5)

! Deshabilitar CDP/LLDP donde no hace falta
interface fa0/1
 no cdp enable

11.2 DHCP Snooping

ip dhcp snooping
ip dhcp snooping vlan 10,20
interface gi0/1                      ! puerto hacia el servidor DHCP / troncal
 ip dhcp snooping trust
interface range fa0/1 - 9
 ip dhcp snooping limit rate 10      ! paquetes por segundo
show ip dhcp snooping
show ip dhcp snooping binding

11.3 Dynamic ARP Inspection

ip arp inspection vlan 10,20
interface gi0/1
 ip arp inspection trust
show ip arp inspection

11.4 Storm Control

interface fa0/1
 storm-control broadcast level 20
 storm-control action shutdown
Packet Tracer soporta DHCP snooping y port security en el 2960, pero algunas funciones (DAI, storm-control) pueden no estar disponibles en todos los modelos o versiones. Si un comando no se reconoce, prueba con un 3560.

Lab 12 · DHCP (servidor en router o switch L3) y relay

Objetivo: asignar IP automáticamente a cada VLAN.

Topología: la del Lab 6 (router-on-a-stick). PCs en modo DHCP (IP Configuration → DHCP).
! En el Router (o switch L3)
ip dhcp excluded-address 192.168.10.1 192.168.10.20
ip dhcp excluded-address 192.168.20.1 192.168.20.20

ip dhcp pool VLAN10
 network 192.168.10.0 255.255.255.0
 default-router 192.168.10.1
 dns-server 8.8.8.8
ip dhcp pool VLAN20
 network 192.168.20.0 255.255.255.0
 default-router 192.168.20.1
 dns-server 8.8.8.8

! Si el servidor DHCP está en otra red: relay en la interfaz del gateway
interface gi0/0.10
 ip helper-address 10.0.0.100

Verificación

show ip dhcp binding
show ip dhcp pool
! En la PC: ipconfig /renew

Lab 13 · ACL para controlar el acceso

Objetivo: permitir solo a IT administrar el switch y bloquear Ventas → IT.

! ACL estándar para limitar VTY a la red IT
access-list 10 permit 192.168.20.0 0.0.0.255
line vty 0 15
 access-class 10 in

! ACL extendida: bloquear VLAN 10 hacia VLAN 20 (en el router o L3)
ip access-list extended BLOQUEO-VENTAS
 deny ip 192.168.10.0 0.0.0.255 192.168.20.0 0.0.0.255
 permit ip any any
interface gi0/0.10
 ip access-group BLOQUEO-VENTAS in

Verificación

show access-lists
show ip interface gi0/0.10 | include access list
Reglas de oro: se evalúan de arriba abajo, hay un deny any implícito al final, y las extendidas se colocan cerca del origen.

Lab 14 · Respaldo, restauración y recuperación

Objetivo: guardar configuraciones, usar TFTP y restaurar un switch.

Topología: SW1 ── Server0 (servicio TFTP activo, IP 192.168.99.10) ── misma VLAN 99.
! Respaldo a TFTP
copy running-config tftp:
 Address or name of remote host []? 192.168.99.10
 Destination filename [SW1-confg]?

! Restaurar
copy tftp: running-config

! Respaldo local
copy running-config flash:backup.cfg

! Dejar el switch de fábrica
erase startup-config
delete flash:vlan.dat
reload

Recuperar contraseña (hardware real 2960)

  • Mantén pulsado Mode al encender hasta ver switch:
  • flash_init → rename flash:config.text flash:config.old → boot
  • Ya dentro: rename flash:config.old flash:config.text → copy flash:config.text system:running-config → cambia las contraseñas y guarda.
Esta recuperación no se puede hacer realmente en Packet Tracer, pero conviene conocerla para el examen CCNA.
