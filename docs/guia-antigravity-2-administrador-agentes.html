0. Primero: qué aplicación tienes

La aplicación de tu captura es Antigravity 2.0, la aplicación independiente orientada a administrar agentes. No es el editor de código tradicional.

Antigravity 2.0

Es un centro de control para iniciar agentes, asignarles tareas, organizar proyectos, revisar artefactos y coordinar trabajo en paralelo. Puede operar sobre carpetas locales y realizar tareas sin que tengas que mantener abierto un editor.

Antigravity IDE

Es el entorno de desarrollo con explorador de archivos, editor de código, terminal y capacidades de agente integradas. Google recomienda conservarlo si programas habitualmente.

Importante: en Antigravity 2.0 no existe un botón para convertir la pantalla actual en un editor de código completo. Son aplicaciones separadas. Puedes usar ambas: el administrador para coordinar agentes y el IDE (o VS Code) para editar y depurar manualmente.

La guía se concentra en la aplicación que ya tienes instalada y en los elementos que aparecen en tu captura. Algunas etiquetas pueden variar según la versión y el idioma.

2. Cuatro conceptos que debes dominar

Project

Es el contenedor lógico del trabajo. Puede incluir una o varias carpetas o repositorios relacionados. Define el contexto y los límites a los que acceden los agentes.

Conversation / Agent

Es una sesión de trabajo. Le describes un objetivo, el agente analiza el contexto, propone o ejecuta acciones y presenta resultados para revisión.

Artifact

Es un resultado visible del agente: por ejemplo un plan, un informe, una propuesta o una revisión de cambios. Sirve para inspeccionar y comentar su trabajo.

Worktree

Es un espacio de trabajo Git aislado. Permite que una tarea trabaje separada de tu carpeta principal, reduciendo conflictos entre trabajos paralelos.

Ejemplo: crea un Project llamado Inventario Flask, agrega la carpeta de tu aplicación y abre una conversación para implementar el módulo de productos. Otra conversación podría revisar pruebas o documentación.

3. Crear tu primer Project

  1. En la barra izquierda, localiza el icono de carpeta con el signo + junto a Projects.
  2. Selecciona New Project.
  3. Escribe un nombre claro, por ejemplo Flask - Sistema de inventario.
  4. Usa Add Folder y selecciona la carpeta real de tu proyecto. Ejemplo: C:\Projects\inventario-flask.
  5. Si el proyecto tiene frontend y backend en carpetas/repositorios separados, puedes agregar más de una carpeta relacionada.
  6. Presiona Create.
  7. Abre la configuración del Project y revisa sus permisos antes de iniciar tareas.
Consejo: no agregues todo tu disco C: como carpeta de un proyecto. Agrega únicamente las carpetas que el agente necesita. Así reduces accesos innecesarios y confusiones.

¿Project o conversación independiente?

Para modificar un sistema existente, usa un Project asociado a sus carpetas. Para una consulta general, lluvia de ideas o investigación que no necesita acceder a tu código, una conversación independiente puede ser suficiente.

4. Iniciar y dirigir un agente

  1. Selecciona el Project correspondiente.
  2. Haz clic en New Conversation.
  3. Escribe una instrucción que explique el resultado que necesitas, las restricciones y cómo comprobarlo.
  4. Cuando aparezca la selección de modo, elige Local o New Worktree según el tipo de trabajo.
  5. Lee el plan o las preguntas del agente. No aceptes operaciones que no entiendas.
  6. Supervisa el progreso y revisa los archivos modificados.

Plantilla de una buena instrucción

OBJETIVO:
[Qué resultado necesito.]

CONTEXTO:
[Qué aplicación es y cómo está organizada.]

ALCANCE:
[Archivos o módulos que puede modificar.]

RESTRICCIONES:
- No cambies tecnologías ni dependencias sin consultarme.
- No elimines funcionalidades existentes.
- Mantén el estilo y convenciones actuales.
- No modifiques archivos de configuración sensibles.

VERIFICACIÓN:
- Ejecuta las pruebas disponibles.
- Comprueba errores de sintaxis.
- Resume los archivos modificados.
- Indica cualquier prueba que no hayas podido ejecutar.

Antes de hacer cambios importantes, presenta un plan.
Evita instrucciones vagas. En vez de “mejora mi aplicación”, indica qué pantalla, qué comportamiento esperas y qué no debe cambiar.

5. Local Mode y New Worktree Mode

ModoQué ocurreRecomendación
Local ModeEl agente trabaja directamente sobre las carpetas activas del Project.Úsalo para cambios pequeños y controlados cuando tienes respaldo o Git.
New Worktree ModeSi el repositorio tiene Git, crea un espacio de trabajo separado para esa conversación.Úsalo para tareas grandes, experimentos o agentes trabajando en paralelo.
Un worktree no sustituye un respaldo. Si la carpeta no está configurada como repositorio Git, el comportamiento puede recurrir a la carpeta local. Verifica el estado del repositorio y confirma dónde se aplicarán los cambios.

Flujo sugerido antes de una tarea grande

Guardar cambios→Commit en Git→Crear conversación→New Worktree→Revisar y probar

6. Files, Review y los cambios del agente

Files

Abre la vista Files para explorar los archivos asociados al trabajo/proyecto según el contexto disponible. Úsala para ubicar el resultado, no como sustituto de una revisión de código.

Review

Abre Review para inspeccionar los cambios propuestos. Busca el diff: qué líneas se agregaron, cuáles se eliminaron y en qué archivo.

Cómo revisar un cambio

  1. Identifica todos los archivos modificados.
  2. Abre cada diff y revisa el contexto alrededor de las líneas cambiadas.
  3. Comprueba que no haya contraseñas, tokens, claves API ni datos privados añadidos.
  4. Verifica que no se hayan eliminado funcionalidades o estilos necesarios.
  5. Ejecuta la aplicación y sus pruebas desde tu entorno de desarrollo.
  6. Conserva o descarta los cambios utilizando el flujo de revisión disponible en tu versión.
En tu captura aparece “2 files changed, +1122 -0”. Eso indica dos archivos con 1.122 líneas añadidas y ninguna eliminada. Revisa el contenido completo: muchas líneas nuevas pueden ser correctas, pero también pueden contener código duplicado o innecesario.

7. Terminal y permisos

La opción Terminal permite consultar la actividad de comandos y, según la versión y el contexto, interactuar con una terminal. El agente también puede solicitar ejecutar comandos para instalar paquetes, correr pruebas o iniciar servicios.

Antes de aprobar un comando

  • Lee el comando completo y comprueba en qué carpeta se ejecutará.
  • Ten especial cuidado con del, rmdir, Remove-Item, scripts descargados y comandos que cambien permisos.
  • No compartas credenciales ni pegues claves API en conversaciones.
  • Revisa si el comando instala dependencias o modifica archivos de configuración.
  • Para bases de datos, exige respaldo antes de ejecutar migraciones destructivas o borrar datos.

En Settings → Project Settings → Agent Settings puedes encontrar controles relativos a ejecución de terminal, acceso a archivos fuera de las carpetas del Project y sandbox, según plataforma y configuración.

Regla práctica: para empezar, conserva las opciones de confirmación. No configures permisos amplios para que el agente ejecute cualquier comando sin preguntar.

8. Comandos útiles para escribir en el prompt

Antigravity 2.0 admite comandos con barra. Escribe / en el cuadro de entrada para consultar las opciones disponibles en tu versión.

ComandoUsoEjemplo
/goalIndica que el agente continúe hasta completar el objetivo, sin detenerse a pedir confirmación intermedia para cada paso normal./goal Implementa la búsqueda de productos y ejecuta las pruebas.
/grill-meHace que el agente te entreviste para aclarar requisitos antes de implementar./grill-me Quiero crear un módulo de inventario.
/schedulePrograma una tarea futura o recurrente mediante Scheduled Tasks./schedule Revisa semanalmente los enlaces rotos del sitio.
/browserSolicita explícitamente el uso del navegador para investigación o comprobaciones web./browser Comprueba el flujo de registro en Chrome.
No interpretes /goal como autorización para saltarse la seguridad: sigue revisando permisos, comandos peligrosos y cambios importantes. La disponibilidad y sintaxis exacta puede cambiar; el menú que aparece al escribir / es la referencia de tu instalación.

9. Automations y tareas programadas

La sección Automations sirve para administrar ejecuciones que no necesitas iniciar manualmente cada vez. Antigravity 2.0 incorpora Scheduled Tasks, incluyendo programaciones recurrentes y temporizadores de una sola ejecución.

Ideas de uso para un desarrollador:

  • Una vez por semana: revisar documentación pendiente del proyecto.
  • Cada mañana: analizar un conjunto de registros de prueba y generar un resumen.
  • Una sola vez: ejecutar una tarea de mantenimiento a una hora futura.

Cómo diseñar una automatización responsable

  1. Define una tarea acotada y repetible.
  2. Especifica el proyecto y los archivos que puede consultar.
  3. Indica qué debe entregar: por ejemplo, un informe, no cambios automáticos.
  4. Configura una frecuencia razonable y revisa la zona horaria.
  5. Comprueba el resultado de la primera ejecución antes de dejarla recurrente.
No programes inicialmente tareas que borren archivos, desplieguen a producción o modifiquen bases de datos reales sin revisión humana.

10. Customizations: Skills, MCP y extensiones

Esta sección permite ampliar lo que el agente sabe hacer o las herramientas con las que puede interactuar. Los elementos concretos que aparecen dependen de tu versión y configuración.

Skills

Instrucciones reutilizables para enseñar al agente un procedimiento especializado. Por ejemplo, convenciones para crear módulos Flask o revisar un proyecto Laravel.

MCP servers

Conectan el agente con herramientas o fuentes de datos externas mediante el Model Context Protocol. Revisa cuidadosamente qué datos y acciones permite cada servidor.

Extensions

Integraciones o extensiones disponibles para añadir capacidades al entorno. Comprueba el origen y los permisos antes de instalarlas.

Hooks

Reglas o acciones configurables que pueden intervenir en determinados momentos del ciclo del agente, según las capacidades habilitadas.

Ejemplo de Skill que te sería útil: “Desarrollar aplicaciones Flask siguiendo mi estructura MVC, usando Flask-MySQLdb, sin SQLAlchemy ni Flask-WTF, con consultas parametrizadas y plantillas Tailwind”. La Skill debería contener instrucciones concretas, no solamente una descripción general.

11. Ejercicio práctico: crear una página sencilla

Vamos a practicar con una carpeta de prueba, no con tu proyecto de producción. Crea una carpeta C:\Projects\antigravity-practica y agrega un archivo index.html vacío o una página sencilla.

Parte A — Crear el Project

  1. Crea el Project Antigravity - Práctica HTML.
  2. Agrega solamente la carpeta de práctica.
  3. Inicia una conversación en Local Mode para este ejercicio pequeño.

Parte B — Pedir un plan antes de editar

/grill-me
Quiero crear una página web personal de presentación con HTML y CSS.
Debe ser adaptable a móviles, tener una sección de presentación,
servicios, proyectos y contacto. No uses frameworks ni JavaScript.
Antes de modificar archivos, pregúntame lo necesario y presenta
un plan de implementación.

Parte C — Implementar

Cuando estés de acuerdo con el plan, solicita la implementación:

/goal
Implementa la página aprobada. Separa el contenido en index.html
y styles.css. Usa HTML semántico, CSS responsive y buenas prácticas
de accesibilidad. No agregues dependencias. Al terminar, revisa
los archivos y explica cómo abrir la página en el navegador.

Parte D — Revisar

  1. Abre Review y examina los dos archivos.
  2. Abre Files y localiza index.html y styles.css.
  3. Abre la carpeta en tu navegador o IDE y comprueba el diseño.
  4. Si algo está mal, pide una corrección concreta en la misma conversación.
Objetivo del ejercicio: aprender el ciclo completo: Project → conversación → instrucción → ejecución → Review → prueba. Cuando domines esto, repite el flujo con una tarea pequeña de Flask o Laravel.

12. Reglas de seguridad para trabajar con tus proyectos

  • Git antes de cambios grandes: confirma tu trabajo o crea una rama antes de pedir refactorizaciones.
  • Respaldo: conserva una copia independiente de proyectos importantes.
  • Secretos: nunca incluyas archivos .env, contraseñas, tokens o claves privadas en prompts o repositorios.
  • Base de datos: utiliza una base de pruebas; revisa migraciones y scripts antes de ejecutarlos.
  • Producción: no permitas despliegues automáticos sin revisar el diff, las pruebas y el destino.
  • Permisos mínimos: agrega al Project únicamente las carpetas que necesita el agente.
  • Revisión humana: el código generado puede contener errores aunque el agente indique que terminó correctamente.

Si el agente no encuentra tus archivos

  • Confirma que abriste el Project correcto.
  • Comprueba que agregaste la carpeta correcta y que la ruta existe.
  • Revisa los permisos de acceso a carpetas.

Si no ves un comando o una opción

  • Escribe / en el cuadro de entrada para ver los comandos habilitados.
  • Revisa Settings y la documentación oficial, porque algunas funciones dependen de la versión.
  • Comprueba si estás en Antigravity 2.0 o en Antigravity IDE: no tienen exactamente la misma interfaz.

Si quieres editar como en VS Code

Abre el proyecto en Antigravity IDE o en VS Code. Antigravity 2.0 puede seguir funcionando como administrador de agentes, mientras el IDE se utiliza para editar, navegar por el código y depurar.
